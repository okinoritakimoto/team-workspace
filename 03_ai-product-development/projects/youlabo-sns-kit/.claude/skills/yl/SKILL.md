# yl — タスクリストを1つずつ進める入口

> **進捗の正本は `TASKS.md`**。プロンプトの原文は `phases/<フェーズ番号>.md`（シートから生成。手で書き換えない）。
> 成果物はタスクごとに1ファイル。置き場は `TASKS.md` の「成果物の置き場」列に従う。

## 使い方（引数）

| 打つもの | やること |
|---|---|
| `/yl` または `/yl 次` | `TASKS.md` で最初の `[ ]` のタスクを1つ実行する |
| `/yl 1-05` | ID のタスクを実行する（前のタスクが未完でも実行してよいが、足りない前提は最初に伝える） |
| `/yl 状況` | フェーズごとの完了数と、次にやる3タスクを出す。何も書き換えない |
| `/yl フェーズ3` | そのフェーズの未完タスクを一覧で出し、どれから行くか聞く |

## 最初に読む（毎回）

1. `CLAUDE.md` — 前提ルールと6セクション
2. `TASKS.md` — どこまで済んだか
3. `rules/判断基準.md` — あれば。好み・避ける表現は毎回ここに従う

## 実行の手順（1タスクごと）

1. `TASKS.md` から対象のタスクを決め、`phases/<フェーズ番号>.md` の同じ ID の節を読む。
2. **前提を集める**: プロンプト中の「私の〜」「これまで決めた内容」「ここまでの」は、`knowledge/`・`research/`・`posts/`・`products/` の既存の成果物を指す。関係するファイルを読んでから答える。プロンプトの「」（空のかぎ括弧）には、`knowledge/concept/` で決めたジャンルやコンセプトを入れる。
3. **前提が足りないときは止まる**: ジャンル・コンセプト・ペルソナなどがまだ無く、推測で埋めるしかない場合は、何が足りないか（どのタスクIDで作るものか）を伝え、ユーザーに聞く。
4. **プロンプトを実行する**: シートの原文どおりに実行する。「私が選ぶので」「確認したら」「OKを出したら」と書かれたタスクは、案を出したところで**止まって選んでもらい**、選ばれてから続きを作る。
5. **素材を入れるタスク**（プロンプトなし）: ユーザーに素材を貼ってもらい、置き場に整理して保存する。
6. **残す**: 成果物を置き場のファイルに保存する。冒頭に `> タスク: <ID> <タスク名> / 作成日: <YYYY-MM-DD>` を入れる。同じファイルが既にあれば、上書きせずに追記する。
7. **印を付ける**: `TASKS.md` の該当行を `[x]` にする。最後に「保存したファイル」と「次のタスクID」を2行で伝える。シート側のチェックは手で付けてもらう。

## 守ること

- **数字や実績を作らない**。売上・フォロワー数・顧客の声は、ユーザーが出したものだけを使う。リサーチで見つからない値は「未確認」と書く。
- **リサーチは出典を残す**。Web で調べた内容には URL を添える。調べられないもの（知恵袋の生の声など）は、推測なら推測と書く。
- **好みを覚える**: フィードバックで好みが分かったら、`rules/判断基準.md` に1行追記する（2-05 で作るテンプレ）。
- **スキル化のタスク**（3-14・5-12）では `.claude/skills/<名前>/SKILL.md` を新しく作り、`/` で呼べるコマンドも `.claude/commands/` に置く。この `yl` スキル自体は書き換えない。
- `phases/` は生成物。シートが変わったら作り直す（手順は `README.md`）。
