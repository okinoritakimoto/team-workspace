# 10_closing — 終結チェックリスト+昇格判定+完了報告書

> 終結トリガーは3つ（どれも正当）: ①目標達成 ②期限到達（2026-11-27） ③中止判断。**延長は存在しない** —
> 続けるなら終結 → 3条件を切り直して別 ID で再発足。状態を「終結処理中」にした直後、メンバーが散る前に一気にやる。
> 中止の場合も9項目すべて通す。終結の判定はリーダー（サンプル）のGOが要る（[../40_process_map/weekly_triangle.md](../40_process_map/weekly_triangle.md) §3）。
> 出どころ: 支援側の運用教科書 第8章（終結）

> **▼ このファイルだけは、いま空欄が正しい状態です。**記入は終結時（目標達成・期限到達・中止判断のどれかが起きた日）から。
> 見本を入れていないのは、埋まっていると「もう終わったのか」と読み違えるためです。**空欄は「まだ終わっていない」の正直な表示**。

## 終結チェック9項目（各項目に完了証跡を添える）

- [ ] ① 成果達成度を確認した（KGI の**いま**の最終値 と **目標**を並べる。未達なら未達と明記）
- [ ] ② 文書・成果物が最新で、課題（ISS）がすべて解決 or 移管済み
- [ ] ③ 成果物を正式に引き渡し、受け入れの承認を得た
- [ ] ④ すべてのコストが請求済み
- [ ] ⑤ 会計を閉じた（この PJ に新たな費用が発生しない）
- [ ] ⑥ メンバーの解放・配置転換（次の行き先が決まっている）
- [ ] ⑦ 資材（作業データ・アカウント・素材）を処分 or 引き継いだ
- [ ] ⑧ 施設・装置（環境・ツール・契約枠）を処分 or 再配分した
- [ ] ⑨ 完了報告書（下記）を作成し、承認を得た

## 正式終結3手順

1. 状態遷移: 終結処理中 → 完了 / 中止（`00_charter.md` の「状態」を更新）
2. 台帳から下ろす: `20_project/` の中身を 支援側の管理先 へ移す（サンプル株式会社に全社の一覧台帳があれば、そこからも外す）
3. 周知: 関係者（`08_stakeholders.md` の全員）に完了報告書を届ける
