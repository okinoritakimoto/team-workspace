# 20_project — プロジェクト正本（PJ-2026Q3-talent-sample・人材プロジェクト（サンプル））

> **30秒**: このプロジェクトの**本物の数字・決定・タスク・リスク**はすべてこの部屋にある。1プロジェクト＝この部屋1つ。
> ダッシュボードや一覧はここから作った鏡（[../60_outputs/](../60_outputs/)）で、鏡を直しても本物は変わらない。

> **▼ いま入っている中身は見本データ（サンプル）です。**実在の個人・組織・実績ではありません。
> 人名はすべて役割名＋（サンプル）。**書き換える前提**で置いてあります（見本を消して、先方の中身を書く）。
> 見本を残したまま実データを混ぜないこと ―― どこまでが本物か分からなくなります。

## 読む順（初めての人）

1. [00_charter.md](00_charter.md) — 何のために・何が出れば成功か・誰が責任者か（憲章8項目）
2. [03_dashboard.md](03_dashboard.md) — いまの数字（計器盤5段）。会議の前に必ず更新される
3. [01_plan.md](01_plan.md) — 何を・いつまでに・誰が（範囲・成果物の束・フェーズとゲート・体制）

発足から初回会議までの順序は root の [README.md](../README.md)「最初の2週間」にある。

## 毎週やること（3分で確かめる）

1. [03_dashboard.md](03_dashboard.md) の5段を更新し、「週ごとの値」に1行足す。
2. `python3 tools/build_dashboard.py` で画面を作り直し、`python3 tools/build_dashboard.py --check` で正本と画面の差を確かめる。
3. 会議で決めたことを [04_tasks/](04_tasks/) と [05_decision_log.md](05_decision_log.md) に落とす（会議が終わる前に）。

## 法則

- **▤ 棚（承認で変わる）** — 憲章・計画・ベースラインは承認で変わる。台帳（05/06/07/11）は**追記で増え、行を消さない**。
- ID は [30_semantic_map/glossary.md](../30_semantic_map/glossary.md) の形だけ（`PJ-2026Q3-talent-sample/WP-01`・`DEC-YYYYMMDD-01`・`PJ-2026Q3-talent-sample/RSK-01`・`T-01`…）。
- **空箱禁止** — 13点は型として最初から置くが、空欄は「まだ決めていない」の正直な表示。埋めた日を鮮度として残す。
- **空欄が正しい唯一のファイル** — [10_closing.md](10_closing.md)（終結時に初めて埋める）。
