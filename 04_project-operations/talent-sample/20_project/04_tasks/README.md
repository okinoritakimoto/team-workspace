# 04_tasks — タスク（1件1ファイル）

> **30秒**: 会議で決めたこと（アクション）を、**担当1人・期限・完了の定義**を付けてここに1件1ファイルで置く。
> **アクション → タスクの変換が、会議が終わる前に済んでいること**がこの部屋の存在理由。証跡欄が空の「完了」は認めない。
> 出どころ: 支援側の運用教科書 第6章（アクション）

> **▼ `T-01.md` 〜 `T-08.md` は見本データ（サンプル）です。**実在の個人・実績ではありません。
> **書き換える前提**で置いてあります。使い始めるときは、支援側が見本8件を除いた初期状態を用意します（この配布キットの中で直接消さない）。その後は `_template.md` を複製して自分のタスクを起こします。
> 見本に置いてあるのは**現役のタスク8件だけ**（完了したタスクのファイルは見本では省略）。実運用では完了したタスクもファイルとして残し、番号は起票順に振ります。

## 記載の原則 ＝ 「frontmatter は9欄、本文は自由」

必須7欄（id・title・wp・assignee＝担当1人・due＝期限・status＝状態・definition_of_done＝完了の定義）＋任意2欄（related・evidence＝証跡。完了時は evidence 必須）。
任意2欄は行ごと省略でき、省略時は `[]` として扱います。frontmatter の欄は上の9つだけで、別の欄は追加しません。長い完了定義や複数の証跡は `../../docs/` に1ファイル置いてリンクで逃がしてよい。
**状態語彙**: 未着手 / 進行中 / レビュー待ち / ブロック / 完了 / 中止（これ以外を発明しない。「保留」は状態ではなく会議録④の保留行に置く。一覧の正本は [30_semantic_map/glossary.md](../../30_semantic_map/glossary.md)）。

## 作り方（3手）

1. `_template.md` を複製する。
2. ファイル名を ID にする（`T-09.md`）。ID は **`T-<連番2桁>`**（このプロジェクトの通し番号。欠番は詰めない）。
3. frontmatter の**必須7欄**を埋め、必要なら任意2欄を足す。会議で決まったタスクなら、本文の1行目に `出所: MTG-…/A-01` を残す。

| frontmatter | 何を書くか |
|---|---|
| `id` | `T-09`（ファイル名と同じ） |
| `title` | 具体的な作業（何をどこまで） |
| `wp` | どの成果物の束（[../01_plan.md](../01_plan.md) §2 の `WP-NN`）か。属さない小事務は `wp: "—"` |
| `assignee` | 担当1人（2人書かない。2人要るなら2件に割る） |
| `due` | 期限（`YYYY-MM-DD`） |
| `status` | 上の状態語彙から1つ |
| `definition_of_done` | 辿れる完了条件（何があれば完了か） |
| `related`（任意） | 関連する ID（`PJ-2026Q3-talent-sample/ISS-01`・`PJ-2026Q3-talent-sample/RSK-02`・`DEC-…`）。省略時は `[]` |
| `evidence`（任意。**完了時は必須**） | URL か repo 内パス。省略時は `[]`。散文は証跡ではない |

> **フルID** ＝ `PJ-2026Q3-talent-sample` ＋ `/` ＋ `T-09`。他の台帳から参照するときはフル形で書く（裸の `T-09` は別プロジェクトと衝突する）。
> **会議のアクション番号との関係**: 会議録の④で決まったアクションは、その会議の中では `A-01` の連番を持つ。台帳へ起票するときに `T-NN` を採番し、本文の「出所」にフル形（`MTG-talent-sample-<YYYYMMDD>/A-01`）を残す。**台帳の ID は `T-NN` に一本化**する（画面の1テーブルと同じ ID で引けるようにするため）。

## 点検の型（週次会議で使う2つの率）

| 率 | 定義 | 悪化時のサイン |
|---|---|---|
| 決定がタスクになった割合 | タスク化されたアクション ÷ 会議の全決定 | 「後で割り振り」が発生している（炎上の型①の入口） |
| **実行率** | 完了タスク ÷ **期限が来た**タスク | サイズ過大・優先度混乱・ブロック放置 |

> **実行率**（完了÷期限到来）と**実施率**（今週実績÷週の予定・KDI で使う）は別の数です。言い分ける。
> 見本の第3週: 期限到来9件・完了7件 → **実行率78%**。未完了2件は `T-01`・`T-02`（[../03_dashboard.md](../03_dashboard.md) 4段目と一致）。

## 記帳規約（迷いどころの正解・全部で7つ）

1. **ID**: 他から参照するときは**フルID**で書く（裸の `T-01` は別プロジェクトの `T-01` と衝突する）。
2. **WP**: そのタスクがどの成果物の束（[../01_plan.md](../01_plan.md) §2 の `WP-NN`）に属すかを必ず書く。属さない小事務は `—`。
3. **証跡の書き方**: クリックか検索で辿れる形 — URL か repo 内パス。散文（「〜のリンク」等）は証跡ではない。
4. **期限変更**: 無言で上書きしない。「初回期限→現期限」を併記し、変更の判断は会議④か DEC- に1行残す（黙って延ばすと実行率が嘘をつく）。
5. **担当交代**: 「担当（現/前）」の併記に直し、交代の判断を DEC- に1行残す。不在時の代理も同様。
6. **分割**: サイズ過大なら子タスクを新IDで起こし、親のIDを子の内容欄に「親: `T-NN`」と残す（子が全部完了した時点で親を完了に）。
7. **完了の2段ゲート**: 「状態＝完了」は担当が証跡を添えて**随時**セット。**検収は次回会議の⓪で全員が見る**。証跡の確認は PM（専門の判断が要る時だけ、その場で reviewer を決めて会議録に書く）。保留の復帰は会議④で新IDを採番し「復帰元: `T-NN`」を残す。

## 迷いどころ（その場で決められる形にする）

| 迷い | 判定 | 見本での実例 |
|---|---|---|
| これは**タスクか、もっと大きい塊（WP）か** | **1週間以内に「終わった」と言い切れるか**。言い切れないなら WP へ上げて割り直す | 「受け入れ手順書の残り12項目を書く」は `T-06`（1週間で終わる）。「受け入れ準備20項目」全体は `WP-08` |
| これは**タスクか、課題（ISS）か** | **自分たちの手で終わらせられるか**。他の人の判断待ちで進まないなら ISS も起こす | `T-01`（稟議を出す）は自分でできる → タスク。枠が落ちている状態そのものは PJ-2026Q3-talent-sample/ISS-01 |
| これは**タスクか、リスク（RSK）か** | **もう起きているか、まだ起きていないか**。まだなら RSK。監視サインを数字で書く | 「辞退が2割を超えると母数が枯れる」は PJ-2026Q3-talent-sample/RSK-02（まだ起きていない） |
| **ブロック**にしてよいか | 自分の作業では動かせない詰まりがあるときだけ。**ブロックに置いたら、対応する ISS を必ず1件起こす** | `T-01` が**ブロック** ↔ PJ-2026Q3-talent-sample/ISS-01（面談枠が週4人ぶんへ落ちている）。この対でひと組 |
| **レビュー待ち**か**進行中**か | 自分の手を離れて他の人の番になっていれば レビュー待ち | `T-02` は案を出して相手の番 → レビュー待ち |
| 決定を**保留**にしてよいか | 理由と**再検討日**が書けるときだけ。担当・期限・完了の定義が埋まらない決定はタスクにせず、会議録④の「保留」行へ | （見本なし。保留は `status: 保留` のタスクを作らず、会議録の保留行に理由と再検討日を書く） |
| いつ **会議の議題**へ上げるか | 期限を過ぎた・ブロックになった・期限変更が必要になった、のどれか | `T-01`（2日 遅れ・ブロック）と `T-02`（1日 遅れ）は 2026-09-07 の会議⓪と⑤で扱う |

## 保留（タスク化できなかった決定）

担当・期限・完了の定義のどれかが埋まらないものはタスクにしない。会議録④の「保留」行に**理由と再検討日**を書く（`status: 保留` のタスクは作らない）。

## 一覧が欲しくなったら

人ごと・WPごとの横断一覧は**このフォルダから生成する**（手で二重に管理しない）。生成物は `../../60_outputs/` に置き、生成日を書く。
画面（タスク＝看板と一覧表）に出るのは**現役**（完了・中止**以外**）のタスクだけ。

## 法則

- **▤ 棚** — 1件のタスクの中身は担当とレビュー担当の合意で変わる。過去の状態変化は本文の「更新の記録」に追記する。
