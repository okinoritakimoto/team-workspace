# 週次運転会議（`bodies/weekly.md`）

> 場の定義は1場1ファイル。**この `weekly.md` は最初から置いてあります**（運転開始の関門を手作業のコピーにしないため）。
> 中身は見本（サンプル）です。表の値を先方の実態へ書き換えれば、そのまま使えます。
> 場の識別は「このプロジェクト＋場のキー」。新しいIDの体系は作らない。

| 項目 | 記入欄 |
|---|---|
| 場のキー | weekly |
| 表示名 | 週次運転会議 |
| 種別 | 週次 |
| 目的 | 事実（数字）を見て、原因と施策を話し、アクションを決めてタスクにする |
| ここで決められること | 運転上のアクション（ベースライン変更は決めない → 重要意思決定の場へ） |
| リズム・時間 | 毎週月曜 09:00〜10:00（サンプル）（**この枠が正本**。長さも枠に合わせる。見本の会議録では第4週を 2026-09-07 09:00〜09:30 の30分で開いています（枠が正本。30分は短縮開催の例で、固定アジェンダ⓪〜⑥は60分を前提）） |
| 進行役 | PM（サンプル） |
| 必ず出る人 | PM（サンプル）・各WPのリード（現場責任者・採用担当A・採用担当B・事務担当・受け入れ担当／すべてサンプル） |
| 出てほしい人 | リーダー（サンプル）（月1回以上。**決めどころがある回は必ず**） |
| 入力（会議前に揃っているもの） | [../../03_dashboard.md](../../03_dashboard.md)（更新済み）・前回の④で決めたタスクの状態 |
| 出力（会議が終わる時にあるもの） | タスク（[../../04_tasks/](../../04_tasks/)）・決定（[../../05_decision_log.md](../../05_decision_log.md)）・課題（[../../07_issue_ledger.md](../../07_issue_ledger.md)）・変更受付（[../../11_change_log.md](../../11_change_log.md)）・次回議題 |
| 議事の雛形 | [../_meeting_template.md](../_meeting_template.md) |
| 状態 | `active` |
| 次回 | 2026-09-07 09:00 |

**状態の欄には英語の値を書く**（日本語は読むための言い方）。支援側の元の型と同じ値をそのまま使い、言い換えで食い違わないようにする。

| 書く値 | 読み方 | いつ |
|---|---|---|
| `draft` | 案 | 場を作ったばかり。まだ開いていない |
| `pilot` | 試行 | 数回開いて、形を試している |
| `active` | 運転中 | 定期で回っている |
| `retired` | 終了 | この場は開かない（行は消さず状態だけ変える） |

## 固定アジェンダ（毎週この並び・順番を入れ替えない）

> **記入のコツ**: ⓪を飛ばさない。⓪（前回の検収）を飛ばした瞬間に、決めたことが追われなくなる。

| # | 議題 | 時間 |
|---|---|---|
| ⓪ | 前回アクションの確認（検収）— 実行率を出す | 10分 |
| ① | 数字の確認（KGI・KPI・KDI・出来高・健全性5観点） | 10分 |
| ② | 原因の話し合い（律速はどこか） | ③と合わせて最長 |
| ③ | 施策の話し合い | — |
| ④ | アクション決定 → タスク化（担当1人・期限・完了の定義） | 10分・必ず確保 |
| ⑤ | 課題・ブロッカー・リスクの新規・状態変化・変更受付の棚卸し | 5分 |
| ⑥ | 気づき・なるほどメモ（行き先を1つ選ぶ） | 5分 |
| 閉 | 会議を閉じる（PM・5項目。画面の作り直しは AI に `/talent 画面` と頼んでもよい） | 5分 |

## 次回の議題（2026-09-07 09:00〜10:00・★＝この回で決めること）

> **記入のコツ**: 「決めること」に **★** を付ける。★が0個の回が続いたら、その会議は報告会になっている。

| # | 議題 | ★ |
|---|---|:---:|
| ⓪ | 先週タスクの検収（期限到来9件・完了7件・実行率78%） | |
| ① | 数字の確認（KGI 4/20人・面談18/90人・確定率22%・準備40%） | |
| ② | **決めどころ1: 面談官2名を追加して4名体制（週8人）へ戻すか** | **★** |
| ③ | **決めどころ2: 書類確認を1段ふやして確定率を30%へ上げるか** | **★** |
| ④ | 遅れている2件（T-01・T-02）の期限の決め直しと解除確認 | |
| ⑤ | 第3週の面談5人（予定8人）の振り返り | |
| ⑥ | 次回の議題 | |

| 項目 | 値 |
|---|---|
| 出席（予定） | リーダー（サンプル）・現場責任者・採用担当A・採用担当B・事務担当・受け入れ担当（すべてサンプル）／進行 PM（サンプル） |
| なぜこの日か | 2026-09-07 は**残り9週の初日**。ここで決めないと9週が8週になり、必要ペースが週8人から**週9人**へ上がる |

## 健全性（この場が機能しているか・月次点検で見る）

| 指標 | 出し方 | 目安 | 見本の値 |
|---|---|---|---|
| 決定がタスクになった割合 | タスク化された決定 ÷ 会議の全決定 | 100%（下がったら「後で割り振り」が起きている） | 7件/7件 ＝ 100%（2026-08-28 の回） |
| 実行率 | 完了 ÷ 期限到来 | 週次で見る。分母0なら「対象なし」と書き100%にしない | 7件 ÷ 9件 ＝ 78%（第3週） |
