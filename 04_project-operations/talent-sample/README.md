# talent-sample — 人材プロジェクト（サンプル）の運転席（見本の配布キット）

> **このフォルダが何をするか**
> サンプル株式会社の「人材プロジェクト（サンプル）」を、**正本1か所・週次の運転・見える計器盤**で最後まで走らせるための型です。**いま入っているのは見本データ**で、実在の人・実績ではありません。
>
> **版と正本**: このフォルダは支援側が管理する元のリポジトリ（配布版 2026-09-04（第2版））からの写し（凍結した見本の配布キット）です。数字を直すときは支援側の担当へ伝えてください（送り方は [../README.md](../README.md)「週次の数字の送り方」）。引き渡し（このフォルダを正本にする）は、このリポジトリが非公開になってから、日時・公開者・戻し先を決めて行います（手順は [docs/member-guide.md](docs/member-guide.md) 7章）。
> **運用の分担（当面）**: PM は数字を送る／支援側が正本の更新・画面の生成・公開を行う。引き渡し後は同じ手順を PM が行います。
> **手元に持ってくる**: GitHub の Web では画面は動きません。落とし方は [../README.md](../README.md)「手元に持ってくる」。
> 期間: 2026-08-17 〜 2026-11-27 ／ 責任者（PM）: PM（サンプル） ／ リーダー: リーダー（サンプル） ／ 支援: 支援側（サンプル）

**最初に見るのは3つ**: この `README.md` ／ [20_project/](20_project/README.md)（正本。数字も決定もここ） ／ ダッシュボード [60_outputs/dashboard/index.html](60_outputs/dashboard/index.html)。
残りの部屋は、この3つを使い始めてから読めば間に合います。

## AI に頼むとき（Claude Code / Codex）

AI（Claude Code / Codex）で**このフォルダ**を開いて **`/talent`** と打つ。覚える入口はこれ1つだけ。

| 打つ言葉 | やってくれること |
|---|---|
| `/talent 今週` | 今週の状態を読み、会議の前にやること（誰が何を更新するか）を出す |
| `/talent タスク` | タスクを起票する・状態を変える（担当・期限・完了の定義が埋まらないものは止まる） |
| `/talent 画面` | 正本から画面（運転席）を作り直す（道具1コマンド） |
| `/talent 会議` | 会議録を作り、決めたことを台帳へ入れる |
| `/talent 名前` | 組織名・担当者名・期間・会議の枠を入れ替える |

中身は [.claude/skills/talent/SKILL.md](.claude/skills/talent/SKILL.md)（Codex 用の同じ本文は `.agents/skills/talent/`）。


## 画面の見方（1ファイルに5つの画面。上の切り替えで移り、押すと右から詳しく開く）

| 画面 | 答える問い | 読む順（上から） |
|---|---|---|
| **全体** | **いま健全か・目標に対していまどこか・今週何を決めるか**（リーダー） | 健全性5つの観点（信号）→ 最終目標（KGI）の環ゲージ（いま・今日までの予定・このペースの見込み・目標）と今週の一言 → 今週決めること（採ると着地）→ 途中の数字（KPI）→ スケジュール（フェーズとゲート）→ タスクの状態と、効いているリスク・課題。KGI・KPI・観点を押すと右から詳しく（推移・着地の見取り図・判定の理由） |
| **タスク** | **自分は何をいつまでにやるのか**（メンバー全員） | 看板（状態のレーン）と期限順の一覧（1行）を切り替え。スマホは一覧が既定。状態・担当・遅れで絞れる。カード／行を押すと右から完了の定義 |
| **メンバー** | **誰が何を握っていて、進んでいるか**（リーダー・PM） | 人ごとの横長カード: 役割・順調か・担当の束（責任者の束と役割ごとの数）・現役タスクと遅れ・月別の稼働・次の期限。押すと右から全部（行動量・関与・前回の会議の自分のぶん） |
| **工程表** | **いつ何があり、余日はいくつか**（PM・リーダー） | 1本の時間軸にフェーズの帯 → 成果物の束 → タスク → 人の稼働。今日の線・余日（今日→期限）・遅れ（期限→今日の赤い帯）・ゲートの丸。行を押すと右から詳しく |
| **会議** | **前回の検収・今週決めること・次回**（出席者） | 「前回・今週」の2枚（左右にスライドで次回）。頭に検収・決めたアクション・タスクになった率／実行率・遅れ・決めることの札。検収・決めたアクション・決めること・議題・出席は押すと縦に開く。下に決めたこと（DEC） |

切り替え行の右の **「見る人」** で「全体」と各メンバーを切り替えると、全体の画面に「この人の今週」（行動量・自分のタスク・持っている束・前回の会議）が出て、タスクの画面はその人の行だけになり、メンバー・会議の画面ではその人の行に印がつきます。
見本の札は切り替え行の右に1つだけ。ことばの意味・投影である説明・鮮度はフッターにあります。

言葉が分からなくなったら [30_semantic_map/glossary.md](30_semantic_map/glossary.md)（用語 → 一言訳）。

## 最初の2週間（発足〜初回会議）— この順で6手

型のファイルには**見本の記入例**が入っています。見本の行を自分たちの値に置き換えれば、そのまま運転を始められます。

1. **憲章を埋める**（PM）: [20_project/00_charter.md](20_project/00_charter.md) の8項目と発足3条件。目標は必ず「数値＋期限」まで。
2. **承認者のGO**: 承認者（サンプル）が憲章にGOを出したら、憲章の「状態」を「進行中」に。ここが最初に人が止まる場所。
3. **計画とKPIツリー**（PM）: [20_project/01_plan.md](20_project/01_plan.md)（範囲・成果物の束・**フェーズとゲート**・体制）と [20_project/02_kpi_tree.md](20_project/02_kpi_tree.md)（KGI→KPI→KDI）。ここで **KGI へ至る道を1本に並べ、いちばん詰まりそうな一段（律速）に印を付ける**。
4. **週次会議の場を確定する**: [20_project/09_meetings/bodies/](20_project/09_meetings/bodies/) の `weekly.md` は最初から置いてあります。枠（毎週月曜 09:00〜10:00（サンプル））・出席者・固定アジェンダ⓪〜⑥を自分たちの値に直すだけ。
5. **計器盤の初回更新**（PM）: [20_project/03_dashboard.md](20_project/03_dashboard.md) の5段＋「今週の一言」＋「今週これを決める」＋週ごとの値の1行を埋める。数字が無い段は「初回計測」と正直に書く。**基準日は1つ**にそろえる。
6. **初回の週次会議**: [20_project/09_meetings/_meeting_template.md](20_project/09_meetings/_meeting_template.md) を写し、⓪〜⑥の順で進める（初回の⓪は「前回なし」でよい）。決めたことは会議が終わる前に全部タスクへ。

> 手5で正本を埋めたら、画面を作り直してから会議に臨みます（手順は下の「週次の回し方」手2）。
> **読む量**: 初回会議までの必読は **7ファイル**（この README と、上の6手で開く6ファイル: 00_charter・01_plan・02_kpi_tree・bodies/weekly・03_dashboard・_meeting_template）。うち大半は**記入例**なので、読むというより「見本の行を自分たちの値へ置き換える」作業になります。それ以外の部屋は、使い始めてから読めば間に合う。

## 週次の回し方（運転が始まったら、これだけ守れば回る）

1. **会議の前日まで**（PM。当面は支援側が代行）: [20_project/03_dashboard.md](20_project/03_dashboard.md) の数字と鮮度、「今週の一言」、「今週これを決める」を更新する — 更新が会議の入場券。締切は曜日ではなく「会議の前日まで」（会議の枠を動かせば締切も動く）。
2. **画面を作り直す**（道具1コマンド・PM。当面は支援側が代行）: `python3 tools/build_dashboard.py` → `python3 tools/build_dashboard.py --check`（正本と画面の差を確かめる。0 なら一致）→ ブラウザで開いて確かめる。
3. **会議**（毎週月曜 09:00〜10:00（サンプル））: [20_project/09_meetings/_meeting_template.md](20_project/09_meetings/_meeting_template.md) の ⓪〜⑥ の順で進める。⓪（前回の検収）を飛ばさない。②で**律速がどの一段か**を確かめ、③で「今週これを決める」を決める。
4. **会議が終わる前**: 決めたことを全部タスクにする（担当1人・期限・完了の定義）→ [20_project/04_tasks/](20_project/04_tasks/) に1件1ファイル。
5. **会議の最後5分で閉じる**（PM。当面は支援側が代行）: 決まった「決めどころ」は決定として [20_project/05_decision_log.md](20_project/05_decision_log.md) へ、詰まりは [20_project/07_issue_ledger.md](20_project/07_issue_ledger.md) へ。次週の決めどころと次回の日時を入れ、画面を作り直す（閉じる5項目 → [40_process_map/weekly_triangle.md](40_process_map/weekly_triangle.md) §1）。
6. **月初**: 月次点検（[20_project/09_meetings/_monthly_check_template.md](20_project/09_meetings/_monthly_check_template.md)）でリスク・スコープ・KPIの棚卸し。

人が止まる場所: 憲章の承認は承認者（サンプル）の GO、期限・予算・範囲（ベースライン）の変更と終結の判定はリーダー（サンプル）の GO（承認者同席）。詳細は [40_process_map/weekly_triangle.md](40_process_map/weekly_triangle.md) §3。
