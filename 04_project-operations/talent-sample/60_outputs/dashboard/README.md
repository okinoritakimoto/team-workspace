> **30秒**: `index.html` は `20_project/` の正本を**1枚の画面へ映した投影**です。数字を直したいときは正本を直します。
> 画面は `python3 tools/build_dashboard.py` が正本から作ります。週ごとに更新するのは [20_project/03_dashboard.md](../../20_project/03_dashboard.md)（正本）です。

## いちばん大事な5つ（この5行が守れれば迷いません）

1. **この画面は正本から道具で作る鏡です。** `python3 tools/build_dashboard.py` が [20_project/](../../20_project/) の正本から作ります。手で書き換えません。
2. **週ごとに更新するのは正本**（[20_project/02_kpi_tree.md](../../20_project/02_kpi_tree.md) は計画時・[20_project/03_dashboard.md](../../20_project/03_dashboard.md) は毎週）。会議はその正本を見て進めます（更新が会議の入場券）。
3. **画面の中の数字（JSON）を手で書き換えないでください。** 作り直しは `python3 tools/build_dashboard.py` です。手で直すと、正本と画面のどちらが最新か誰にも分からなくなります。
4. **`python3 tools/build_dashboard.py --check` が 0 なら正本と画面が一致しています。**
5. **名前は** `names.yml` に値を書く → `python3 tools/apply_names.py --rename`（文章の差し替え）→ `python3 tools/build_dashboard.py`（画面に名前が入る）→ 両方の `--check`。

## この画面に何が載っているか（1ファイルに4つの画面）

上の切り替え（または URL の `#dashboard` `#tasks` `#members` `#meeting`）で画面を移ります。切り替え行の右に「見る人」（全体／各メンバー）・見本の札・基準日。

| 画面 | 節（上から） | 答える問い |
|---|---|---|
| **計器盤** | 今週の一言（1行・続きは畳み） | この週の結論 |
| 計器盤 | 健全性 — 5つの観点（信号の列。点の色＋言葉＋理由） | **いま健全か。どこが問題で、どこは大丈夫か** |
| 計器盤 | 最終目標（KGI）のゲージ: いま／今日までの予定／このペースの見込み／目標 の4点を1つの弧に。律速の一段と必要ペースを1行、判定の理由は畳み | **目標に対していまどこか。放っておくとどこに着くか** |
| 計器盤 | 今週決めること（決めどころ・採ると着地の帯・決めずにこのまま） | **今週何を決めるか** |
| 計器盤 | 途中の数字（KPI 4枚: 値・前週比・目標線つきの推移・達成%・鮮度・注記は畳み） | 手前の数字はどうか |
| 計器盤 | スケジュール（フェーズの帯・今日の線・ゲートの判定日と結果） | 節目はいつで、いまどこか |
| 計器盤 | タスクの状態（現役の内訳・出来高 WP・今週の実行率）／ 効いているリスクと課題（監視中は畳み） | 手元はどれだけ片づいているか |
| **タスク** | 看板（状態のレーン）⇄ 一覧表 の切り替え ／ 絞り込み（状態・担当・遅れだけ）／ カード・行を開くと完了の定義 | **自分は何をいつまでにやるのか** |
| **メンバー** | 体制の要約（現役・遅れ・今月の稼働合計）／ 人ごとのカード（役割・担当の束（責任者A／実行R）・月別の稼働・現役タスクと状態の内訳・今週の行動量・次の期限・関与と次の一手は畳み） | **誰が何を握っていて、進んでいるか** |

「見る人」でメンバーを選ぶと、計器盤に「この人の今週」（行動量・自分のタスク・持っている束・前回の会議の自分のぶん）が出て、タスクの画面はその人の行だけになり（担当の絞り込みは「見る人」に譲って止まります）、メンバー・会議の画面ではその人の行に印がつきます。

## 法則

- **◇ 鏡（generated）** — 正本から作る。手編集しない。頭注に生成元・生成日を残す。
- 1ファイル自己完結（CSS／JS を内包・外部通信ゼロ・端末のフォントだけ）。ダブルクリックで開けて、そのまま公開もできる。
- 中身は2層: 上の `<script type="application/json" id="dashboard-data">` が**データ層**、下の HTML／JS が**表示層**。**道具（`build_dashboard.py`）はデータ層だけを書き換えます。表示層（見た目）を変えるのは支援側**です。
- **データ層に置くのは元の数だけ**（実績・目標・期限・期間・週ごとの値・体制・前回の会議録の検収表とアクション）。達成%・実施率・実行率・必要ペース・今日までの予定・週番号・着地の試算・到達日・遅れ・持ちタスク数は**表示層が計算します**（元の数と画面の数字が食い違う経路を作らないため）。データ層の版は `talent-dashboard/v4`（`members[]`・`last_meeting`・`tasks[].dod` を持つ）。
- **見本札** — 正本 `20_project/03_dashboard.md` の見本札が true のあいだ、画面に「見本」の札と注記が出る。false にすると全部消える。

## 「見本」の印 — どこに出るか／実データへ替えるときどうするか

**この画面は全体が見本です。** 数字・人名・タスクだけでなく、表示層のマークアップにも見本の言い回しが入っています。
だから実データへの切り替えは、**印を1つずつ手で外す作業ではありません**（それは上の「いちばん大事な5つ」の3「画面の中の数字を手で書き換えない」と矛盾します）。
データ層は `python3 tools/build_dashboard.py` が正本から作り直します。表示層は見本札（`meta.sample`）を読み、false のとき見本の札と注記を全部消します（支援側が入れた仕組み。見た目を直すのは支援側です）。

**印の全数は、ファイルを「見本」「サンプル」の2語で検索すれば出ます**（数を覚える必要はありません。この探し方なら数え漏れが起きません）。出てくるのは次の6種類です:

| どこ | 何が入っているか | 実データにすると |
|---|---|---|
| 目に見える札・文 | 切り替え行と各画面の「見本」の札・フッターの「データは見本です（数値・人名はすべてサンプル）…正本を自分たちの値に替えて作り直すと、この画面が自分たちの数字になります」 | `meta.sample` が false になると、表示層が `data-live` を立てて**全部消える**（静的に書かれた札は無い） |
| 読み上げ用のラベル | ゲージ・推移・稼働の帯などの図の説明文（表示層が組み立てる）。目には見えないが、読み上げには出る | 同上 |
| データ層の頭注 | `meta.generator`・`meta.note`（＋日本語では書かれていない機械の印 `meta.sample`） | `meta.sample` を `false` にする |
| 表示層のコメント | 担当の役割語に「（サンプル）」を付けない理由の但し書き | 残ってよい（規則の説明であって表示ではない） |
| 名前の欄 | プロジェクト名・組織名・支援側の名乗り・PM・リーダー・週次会議の枠に入っている見本の値 | **`names.yml` を埋めて `python3 tools/apply_names.py --rename` → `python3 tools/build_dashboard.py`**で消える（先方の手で消える印はここだけ） |

**切り替えたあとの検算（2つとも通れば外し忘れゼロ）**

1. 配布ファイルを「見本」「サンプル」で検索して、残るのは表示層のコメント（規則の説明）だけ
2. データ層の `"sample"` が `false` になっている

> 担当の名前は「PM」「リーダー」「現場責任者」のような**役割語**で持っています。実データにしても役割語のままなのが正しい姿で、これは見本の印ではありません（`names.yml` で名前が入るのは PM とリーダーの2人だけ）。

## 公開（みんなで同じ1枚を見る）

**公開しなくても共有はできます。** この画面は1ファイルだけで完結しているので、`index.html` を1枚そのまま渡せば（社内の共有ドライブに置く・メールに添える）、受け取った人の端末でそのまま開けます。

**URL で配るときは、公開・再公開を支援側へ依頼してください。** 公開URLは**このフォルダには書きません**（公開の置き場なので、URL は手引き（Googleドキュメント）で PM が配ります）。`names.yml` の `DASHBOARD_URL` は空のままにします。

画面を作り直したら、そのつど再公開を依頼します（同じ URL へ差し替えてもらう）。依頼しない限り、URL の先は古い画面のままです。

## 公開されたら確かめる4点

1. 公開URLが HTTP 200 を返す
2. ページの題（PJ名 — 計器盤）と「今週の一言」が正本と一致し、4つの切り替え（計器盤・タスク・メンバー・会議）が動く
3. PC幅（1280）とスマホ幅（390）で崩れていない・横スクロールが出ない
4. ログインしていないブラウザ（シークレットウィンドウ）でも開ける

## 入れてはいけないもの

- 実名・メールアドレス・電話番号・顧客情報・本番データ・鍵・公開URLは書かない。人名は役割名（PM／リーダー／面談担当）で書く。
- ローカルの絶対パス・手元のサーバへの参照・外部サイトへの読み込みは置かない（1ファイルだけで開ける状態を壊さないため）。
