# 02_principles — 全員が守る約束（6つ）

> 短い。増やすのは「守れなかった事故」が起きて、会議録⑥（[20_project/09_meetings/](../20_project/09_meetings/)）に記録が残った時だけ。
> 各約束の行末にある「出どころ」は、この形の元になった支援側の運用教科書の章。

## 1. 正本は1か所（`20_project/`）。画面と一覧は投影

数字・決定・タスク・リスクの本物は `20_project/` の Markdown / YAML にだけある。
ダッシュボード（`60_outputs/dashboard/`）や生成した一覧は**正本から作った鏡**で、そこを直しても正本は変わらない。
直したいときは正本を直し、鏡を作り直す。鏡には「いつ・何から作ったか」を書く。

週ごとに更新するのは [20_project/03_dashboard.md](../20_project/03_dashboard.md)（正本）**だけ**。
画面へ反映するのは **画面の作り直し**: 正本を直す → `python3 tools/build_dashboard.py`（画面を作り直す）→ `python3 tools/build_dashboard.py --check`（正本と画面の差を確かめる。0 なら一致）→ ブラウザで開いて確かめる。
それまで画面を手で書き換えない — 手で直すと、正本と画面のどちらが本当か分からなくなる。
**名前の差し替え**は `names.yml` に値を書く → `python3 tools/apply_names.py --rename`（文章の差し替え）→ `python3 tools/build_dashboard.py`（画面に名前が入る）→ 両方の `--check`。
出どころ: 支援側の運用教科書 第4章（モニタリング）

## 2. 記録は消さない。追記する

決定（[20_project/05_decision_log.md](../20_project/05_decision_log.md)）・変更の言い出し（[20_project/11_change_log.md](../20_project/11_change_log.md)）・リスク（[20_project/06_risk_ledger.md](../20_project/06_risk_ledger.md)）は、却下・杞憂と分かっても行を消さず、状態と理由を1行足して閉じる。
過去を書き換えると「なぜこうなっている？」に誰も答えられなくなる。
出どころ: 支援側の運用教科書 第5章（会議体）・第7章（リスク・関係者）

## 3. 数字には鮮度（更新日）を添える

計器盤の数字には必ず「いつの数字か」を添える。鮮度が管理サイクル（週次なら1週間）を超えた数字で判断しない。
古い数字は、無いのと同じではなく、**無いより悪い**（正しいと思って読まれる）。
1回の更新でそろえる**基準日は1つ**にする（画面の中に「いつの値か」が2つ以上あると、どれで判断したのか後から追えない）。
出どころ: 支援側の運用教科書 第4章（モニタリング）

## 4. 状態の言葉を発明しない。同じ語を2つの意味に使わない

タスクは「未着手・進行中・レビュー待ち・ブロック・完了・中止」（保留は状態にせず会議録④の行）、リスクは「監視中・兆候あり・顕在化・クローズ」——
使える言葉は [30_semantic_map/glossary.md](../30_semantic_map/glossary.md) にある分だけ。「ほぼ完了」「だいたい終わってる」は状態ではない。迷ったら「進行中」か「レビュー待ち」に倒し、判断は会議で。
逆に、**同じ語を2つの意味に使わない**。例: **実行率**＝完了 ÷ 期限が来たタスク／**実施率**＝今週の実績 ÷ 週の予定。似ているが別の数なので、言い分ける。
出どころ: 支援側の運用教科書 第1章（用語）

## 5. 人が止まる場所を明示する

人の GO が要ること（憲章の承認＝承認者、期限/予算/範囲の変更と終結＝リーダー）は [40_process_map/weekly_triangle.md](../40_process_map/weekly_triangle.md) に列挙してあり、そこ以外では止めない。
逆に、列挙してあることを GO なしで進めない。
出どころ: 支援側の運用教科書 第2章（立ち上げ）・第8章（終結）

## 6. 個人情報・録音・鍵を置かない

氏名は先方と合意した表記だけ。メールアドレス・電話番号・会議の録音や文字起こし・API の鍵・パスワードは Git に入れない（`.local/` か先方の規程に従った場所へ）。
この repo が誰かに共有されても困らない状態を保つ。
出どころ: 支援側の運用教科書 第7章（リスク・関係者）
