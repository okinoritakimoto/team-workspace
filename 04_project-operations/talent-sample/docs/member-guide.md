# 人材プロジェクトの進め方 — はじめて使う人のための手引き

## はじめに

### この手引きは誰のための、何のためのものか

この手引きは、サンプル株式会社の「人材プロジェクト（サンプル）」を進めるために用意された**フォルダ一式**と、そこから作られる**画面**の使い方を、最初から最後まで書いたものです。読み手として想定しているのは、このプロジェクトで実際に作業をする各担当の方（この手引きでは「メンバー」と呼びます）です。進行役の PM、決める立場のリーダーが読んでも、自分の担当箇所がどこかが分かるようになっています。

前提知識は必要ありません。パソコンでブラウザ（Chrome・Safari・Edge など）が開けて、フォルダの中のファイルをダブルクリックできれば十分です。プログラムを書ける必要も、専門の管理ソフトを覚える必要もありません。この手引きに初めて出てくる言葉は、その場で普通の言い方に置き換えて説明します。

説明の順番は「見る側 → 本物が置いてある側 → 頼み方 → 週の回し方 → 守ること」です。上から順に読めば、知らない言葉が出てくる前に必ずその言葉の説明が済んでいる並びにしてあります。途中から拾い読みする場合は、次の「章の並び」から目的の章へ飛んでください。

### 読み終えたときにできるようになること

この手引きが目指しているのは、次の3つができる状態です。逆に言えば、この3つができれば運用は回ります。ここに出てこないことは、必要になってから覚えて間に合います。

- **自分のタスクを見つけられる**: 画面を開いて表示を自分に切り替え、自分が何を・いつまでに・どうなったら終わりなのかを言える。
- **画面の数字の出どころを辿れる**: 画面に出ている数字が、どのフォルダの・どのファイルの・どの行から来ているかを開いて確かめられる。
- **AI に1つ頼める**: このプロジェクトのフォルダを開いた状態の AI に `/talent` と打ち、今週やることを出す・タスクを起こす・画面を作り直す、のどれかを頼める。

### 章の並びと、それぞれで分かること

| 章 | 分かること | 特に読む人 |
|---|---|---|
| 1章 全体像 | 本物の記録・道具・画面の関係 | 全員 |
| 2章 画面の使い方 | 開き方から自分のタスクまで | 全員 |
| 3章 フォルダとファイル | どこに何が置いてあるか | 全員 |
| 4章 AI への頼み方 | 打つ言葉と、止まる場所 | 全員 |
| 5章 週の回し方 | 前日・当日・最後5分・週の途中 | PM とメンバー |
| 6章 守ること | してよいこと・困ったときの行き先 | 全員 |
| 付録 | この画面と記録に出る言葉の一覧 | 迷ったとき |

### やりたいことから引く

通しで読む時間がないとき、また運用が始まってから調べ物をするときは、この表から入ってください。上の「章の並び」が**覚える順**、この表が**やることから探す順**です。

| やりたいこと | 開く節 |
|---|---|
| はじめて画面を開く | 2章「画面の開き方は2通り」 |
| 自分の担当を見つける | 2章 見る人を自分に切り替える → 自分の仕事の見つけ方 |
| タスクが終わったので状態を変える | 3章「タスクを動かすとき、書き換えるのは2か所です」 |
| 「終わった」と言ってよいか判断する | 2章 完了の定義と、完了にするときに添えるもの |
| 画面の数字がどこから来たか確かめる | 3章「画面の数字から、元のファイルまでの辿り方」→「やってみます」 |
| どのファイルを開けばよいか分からない | 3章「12のフォルダは、それぞれ何のためにあるか」 |
| AI に手伝ってもらう | 4章「覚えるコマンドは `/talent` の1つだけ」 |
| AI が途中で止まった | 4章「AI が必ず止まる場所」 |
| 会議の前日にやることを確認する | 5章「会議の前日まで」 |
| 会議を進行する | 5章「会議当日」→「会議の最後5分」 |
| 見本の数字を自分たちの数字に入れ替える | 3章「いちばん上に置いてある6枚のファイル」 |
| 画面が真っ白・数字が古い | 6章「画面が真っ白・古い数字のままのとき」 |
| 言葉の意味が分からない | 付録「言葉の一覧」 |
| やってよいか迷った | 6章「守ることは6つだけです」 |

### この手引きに出てくる数字・人名は、すべて練習用の見本です

いま画面とファイルに入っている数字・人名・タスクは、使い方を覚えるために置いてある**練習用の値**です。実在の個人・組織・実績ではありません。人名はすべて「PM（サンプル）」「リーダー（サンプル）」のような役割名になっています。

この手引きでも、説明のために「面談 週8人」「受け入れ確定 4人 / 20人」といった値を何度も使います。これらはすべて練習用の値で、読み方をつかむためのものです。業務の判断には使えません。

形（欄の名前・並び・計算の仕方）はそのまま使えるようにしてあるので、実際に運用を始めるときは**値だけ**を自分たちのものに入れ替えます。入れ替え方は3章と4章に書いてあります。

> **この手引きの立場**: この手引きは説明のための文書です。数字・決定・タスクの本物は、いつでも 3章で説明するフォルダ `20_project/` の中のファイルにあります。この手引きと実物が食い違ったときは、実物のファイルが正しいと考えてください。

## 1章 全体像 — 本物は1か所、画面は自動で作られます

### このフォルダ一式は何か

このプロジェクトの記録は、**パソコンの中のただのフォルダ**として置いてあります。特別なソフトは要りません。中に入っているのは次の2種類のファイルで、どちらもメモ帳のような文字を表示するソフトで開けます。

- **Markdown（マークダウン）**: 拡張子が `.md` のファイル。中身はただの文章です。見出しや箇条書きに `#` や `-` といった記号を使うだけの、普通の文字ファイルです。
- **YAML（ヤムル）**: 拡張子が `.yml` のファイル。「項目名: 値」を並べた設定用のファイルです。

1つのプロジェクトにつき、このフォルダ一式が1つです。プロジェクトが増えたら、同じ形のフォルダ一式をもう1つ用意します。

普通の管理ソフトではなくフォルダとファイルで持っているのには理由があります。

- 全員が同じ1つのものを見られる。誰か1人のパソコンにしかない表ができない。
- 誰が・いつ・何を変えたかが記録として残る。
- 文字なので、検索すれば一発で見つかる。
- 特定のサービスが終わっても、ファイルはそのまま読める。

### 置き場所は3つだけ

この一式でいちばん大事なのは、次の3つの関係です。ここさえ分かれば、あとは全部その応用になります。

<!-- flow -->
① 正本 ＝ 本物の記録が置いてあるファイル（フォルダ 20_project/ の中）
　　↓　読んで作る
② 道具 ＝ 正本を読んで画面を作り直す、小さなプログラム（tools/ の中）
　　↓　出す
③ 画面 ＝ 正本から自動で作った、見るためのページ（60_outputs/ の中）

矢印は上から下への一方向だけで、逆向きはありません。つまり、③の画面を書き換えても①の正本は変わりません。直したいことがあるときは、いつでも①の正本を直して、②の道具を1回動かします。

| どれ | 何が置いてあるか | 誰が触るか |
|---|---|---|
| ① 正本 | 数字・決定・タスク・リスク | PM と各担当 |
| ② 道具 | 画面を作り直す1つの命令 | PM（または AI） |
| ③ 画面 | 見るためのページ | 全員（見るだけ） |

### 「正本」と「投影」— この2語の意味を1つに固定します

この手引きでいちばん多く出てくる専門語が「正本」と「投影」です。どちらもこのプロジェクトの中では意味が1つに固定されています。

**正本（せいほん）**とは、**本物の記録が入っているファイル**のことです。ここを直せば、そこから作られるもの全部が変わります。このプロジェクトの正本は、フォルダ `20_project/` の中にあるファイル群です。たとえば今週の数字が入っている `20_project/03_dashboard.md` は正本です。

**投影（とうえい）**とは、**正本から自動で作った見せ方**のことです。直しても本物は変わりません。このプロジェクトの投影は、画面のファイル `60_outputs/dashboard/index.html` です。

この2つを混ぜないことが、この一式でいちばん大事な決まりです。画面のファイルを開いて数字を書き換えても、`20_project/` の中のファイルは1文字も変わりません。そして次に画面を作り直した瞬間、書き換えた数字は消えます。それだけでなく、その間は「正本の数字」と「画面の数字」が違う状態になり、どちらが本当なのか誰にも分からなくなります。だから画面は**見るためだけ**に使い、直したいときは正本を開きます。

> **覚えておくのはこの1行だけです**: 数字を直したいときは `20_project/` の中を直し、そのあと画面を作り直す。

### 誰が何をする人か

このあとの説明は「あなたがどの役割か」で読む場所が変わります。まず自分がどれかを決めてください。名前はすべて役割名（サンプル）です。

| 役割 | この人がやること | 毎週触るもの |
|---|---|---|
| リーダー（サンプル） | 決める人。期限・予算・範囲の変更と、終わりの判定に GO を出す | 画面の「全体」 |
| PM（サンプル） | 回す人。今週の数字を更新し、会議を進行し、決めたことをタスクにして閉じる | 今週の数字と会議録 |
| 各担当（メンバー） | 実行する人。自分のタスクを進め、状態と記録を残す | 自分のタスクのファイル |
| 承認者（サンプル） | 発足に GO を出す人 | 発足時だけ |
| 支援側（サンプル） | この一式と画面の仕組みを用意し、見た目と公開を担当する | 画面の作りと公開の設定 |

この手引きの主な読み手は「各担当（メンバー）」です。メンバーが**自分で書き込むのは、20_project/04_tasks/ の中にある自分の名前が入ったファイルだけ**です。ほかのファイルは読むだけで構いません。書き込む場所が1か所しかないので、間違えて別の記録を壊す心配はほとんどありません。

## 2章 画面の使い方

### 画面の開き方は2通り

画面は**1つのファイルだけで完結**しています。中に必要なものが全部入っていて、外へ通信もしません。だからインストールも会員登録も要りません。開き方は次の2通りで、どちらを使っても同じものが開きます。

- **配られた URL を開く（普段はこちら）**: ブラウザのアドレス欄に、配られた URL を貼り付けて Enter を押します。ログインは要りません。スマートフォンでも開きます。
- **ファイルをダブルクリックする**: 配られたフォルダの中の `60_outputs/dashboard/index.html` をダブルクリックします。インターネットにつながっていなくても開きます。このファイル1枚をそのままメールに添えて送っても、受け取った人の端末で開けます。

ここで1つ注意があります。**URL の先は、作り直しを依頼するまで古いままです。** 画面を作り直しても、URL の先が自動で新しくなるわけではありません。支援側（サンプル）へ「差し替えてください」と依頼したときに新しくなります。いま見ているものが最新かどうかは、画面のいちばん下に出ている「画面の作り直し日」で確かめられます。

### どの画面にも共通する上の部分

5つのどの画面を開いていても、上のほうには同じものが並んでいます。ここだけで「いつの・どのプロジェクトの・誰の目線の数字か」が決まるので、最初に読む場所です。

- **プロジェクト名と状態**: 「進行中」は、立ち上げの決めごとに承認者の GO が出ている状態です。
- **基準日**: 画面のすべての数字がそろっている日。画面の中では1つだけです。
- **5つの画面の切り替え**: 全体・タスク・メンバー・工程表・会議。押すと切り替わります。
- **「見本データ」という表示**: これが出ているあいだ、数字は練習用です。
- **「見る人」**: 全体と各メンバーを切り替えます。ここが自分の名前を選ぶ場所です。
- **画面の色の切り替え**: 右上にある月の形のボタンです。押すと画面の色が明るい／暗いに変わります。中身は変わりません。

### 5つの画面が、それぞれ答える問い

画面は1つのファイルの中に5つ入っていて、上の切り替えで移ります。それぞれが答える問いは決まっていて、重なりません。

| 画面 | 答える問い | いちばん使う人 |
|---|---|---|
| 全体 | いま健全か。目標に対していまどこか | リーダー |
| タスク | 自分は何をいつまでにやるのか | メンバー全員 |
| メンバー | 誰が何を持っていて、進んでいるか | リーダー・PM |
| 工程表 | 節目はいつで、いまどこか | PM・リーダー |
| 会議 | 前回の確認・今週決めること・次回 | 出席者 |

#### 画面①「全体」

リーダーが最初に見る画面です。上から順に、次の並びで読むと話が通ります。

- **健全性（5つの観点の判定）**: スケジュール・スコープ・品質・チーム・リスクの5つを、人が見て 🟢 健全 / 🟡 注意 / 🔴 危険 のどれかに判定したものです。判定の隣には必ず理由が1行付いています。5つのうちいちばん悪い判定が、その週の全体の判定になります。
- **最終目標のゲージ**: 半円の目盛りの図です。目標に対していまどこにいるかと、このまま行くとどこに着くかを、1つの図で見ます。
- **律速（りっそく）**: いちばん詰まっていて、全体の速さを決めているところに付く印です。
- **今週決めること**: まだ決まっていない選択肢と、それを採ったときの見込みです。
- **途中の数字（4つ）**: 最終目標に届くかを手前で測っている数字です。
- **スケジュールとタスクの状態**: 節目の日程と、いま抱えているタスクがどれだけ片づいているかです。

#### 最終目標のゲージの読み方

半円のゲージには4つの点が重なっています。この4行の差を読むのが、この画面のいちばん大事な使い方です。

| 画面の行 | 見本の値 | 意味 |
|---|---|---|
| いま | 4 人 | 今日の時点で実際に届いている数 |
| 今日までの予定 | 5 人 | 計画どおりなら今日届いているはずの数 |
| このペースの見込み | 14 人 | いまのまま期限を迎えたら届く数 |
| 目標 | 20 人 | 期限までに届かせる数 |

読み方は1行で言えます。**「このペースの見込み 14人」と「目標 20人」の差 6人 が、いま放っておくと足りなくなる分**です。この差をどうやって埋めるかを、下の「今週決めること」で決めます。

#### 「律速（りっそく）」

律速とは、**全体の速さを決めているところ**のことです。ここで処理できる数が増えないかぎり、手前や後ろをいくら増やしても最後の数は増えません。

見本の場合、候補者リストは132人あって十分足りています。詰まっているのは面談の本数だけで、いまは週5人しか回せていません。ここを計画どおりの週8人へ戻すだけで、期限までの20人に届きます。逆に、候補者をこれ以上増やしても確定は増えません。これが「まず律速だけを直す」ということです。

律速は動きます。詰まっていたところで処理できる数が増えると、次に少ないところが律速になります。だから月に1回、どこが律速かを見直します。

#### 「今週決めること」

ここに並んでいるのは、**まだ決まっていない選択肢**です。決まったことではありません。それぞれに「誰が決めるか」「いつの会議で決めるか」「採ったら見込みがどう変わるか」が付いています。

見本では次の2つが並んでいます。1つ目を採れば期限の20人に届きます。2つ目は「確定率が上がれば」という条件つきで、上がらなければ16人で終わります。決めずにこのままだと14人です。

| 選択肢（見本） | 採ったときの見込み |
|---|---|
| 面談する人を2名足して週8人へ戻す | 20人・届く |
| 書類確認の段階を1つ増やし、面談官を1名足して週6人にする | 確定率が 22% → 30% になれば20人。ならなければ16人 |
| 決めずにこのまま | 14人・6人足りない |

会議で決まると、その項目はこの欄から消えて「決めたこと」の記録へ移り、この欄には次の決めどころが入ります。ここに載せられるのは一度に2件までです。

#### 「途中の数字」4つ

最終目標にたどり着くまでの通過点になる数字が4つ並んでいます。どのカードにも、値・前の週との差・目標に対する達成の割合・その数字がいつのものか（鮮度）が出ています。

| カード（見本） | 値 | 目標 | 読み方 |
|---|---|---|---|
| 候補者リスト数 | 132 人 | 120 人 | 連絡先が分かり打診できる人 |
| 面談完了数 | 18 人 | 90 人 | 実際に面談を終えた人（律速） |
| 面談→確定率 | 22 % | 30 % | 面談した人のうち決まった割合 |
| 受け入れ準備の完了率 | 40 % | 100 % | 20項目のうち終わった割合 |

達成の割合に上限は付けません。候補者リストの110%は「目標を12人ぶん超えている」という意味で、100%で止めることはしません。

#### 画面②「タスク」

メンバーが毎日いちばん使う画面です。同じ内容を2つの見せ方で切り替えられます。中身は同じものです。

- **「看板」**（ボタンの名前です）: 状態ごとの列にカードを積み上げた形になります。列の高さが、そのまま詰まりの量になります。
- **「期限順」**（同じくボタンの名前です）: 1行1件で、期限の早い順に並びます。遅れ・今週・来週・それ以降にまとまって出ます。

上には絞り込みのボタンが並んでいます。すべて・未着手・進行中・レビュー待ち・ブロックの5つと、「遅れだけ」です。その右に「担当」を選ぶ欄があります。

この画面に出るのは**現役のタスクだけ**です。現役とは、完了と中止以外の状態のことです。終わったタスクは画面から消えますが、ファイルはフォルダに残り続けます。記録は消しません。

#### 画面③「メンバー」

1人につき1つの横長のカードが並びます。カードを押すと、その人の詳しい欄が右から開きます。

| カードの欄 | 読み方 |
|---|---|
| 担当の束 | その人が持つ成果物のまとまり |
| 現役タスク | 終わっていないタスクの件数 |
| 稼働（月別） | 自分の時間のうちこの仕事に使う割合 |
| 次の期限 | いちばん近い期限と、その状態 |

「担当の束」の欄には A と R の印が付きます。**A は説明責任**で、1つのまとまりにつき1人だけです。**R は実行**で、複数人いて構いません。ほかに C（相談を受ける人）と I（結果を共有される人）もあります。「束」というのは、1つの成果物のためにまとまった仕事のことです。

#### 画面④「工程表」

全期間を1本の時間軸に並べた画面です。フェーズ（重点期間）・成果物のまとまり・タスク・稼働が、同じ時間軸の上に載っています。

- 青い縦線が「今日」の位置です。
- 「余日」は、今日から期限までの残り日数です。マイナスなら遅れです。
- ◇ が期限、● が完了を表します。
- 赤い横棒は遅れで、期限から今日までの長さがそのまま出ます。
- 左上の「束のタスクをたたむ」を押すと、大きなまとまりだけの表示に切り替わります。

#### 画面⑤「会議」

「前回」「今週」「次回」の3枚があります。画面に同時に映るのは**2枚まで**で、右上の矢印で送ると次の枚が出ます（画面の幅が狭いときは1枚ずつになります）。会議の場でそのまま映して進められるように作られています。

- **前回**: 前回決めたことが終わったかの確認と、その割合。決めたアクションのいまの状態。
- **今週**: 今週の実行の割合・遅れ・今週決めること。
- **次回**: 出席予定・議題（決める行には印が付きます）・会議の前日までにやること。

下には「決めたこと」が並びます。ここに出てくる**実行率は、完了したタスク ÷ 期限が来たタスク**です。見本では 7件 ÷ 9件 で78%です。似た言葉に**実施率**（今週の実績 ÷ 週の予定）がありますが、これは別の数です。混ぜないように、言い分けてください。

### 「見る人」を自分に切り替える

画面の上の右にある「見る人」で自分の名前を選ぶと、画面全体が自分ごとになります。設定もログインも要りません。

| 画面 | 「全体」のとき | 自分の名前を選んだとき |
|---|---|---|
| 全体 | プロジェクト全体の数字 | 上に「この人の今週」が出る |
| タスク | 現役のタスクすべて | その人の行だけになる |
| メンバー | 全員のカード | その人の行に印が付く |
| 工程表 | 全員ぶんの時間軸 | その人の行に印が付く |
| 会議 | 議題と決めたこと | その人に関係する行に印が付く |

元に戻すときは「全体」を選び直します。この切り替えは**あなたのブラウザの中だけ**の話で、ほかの人の画面は変わりません。なお、自分の名前を選んでいるあいだは、タスクの画面の「担当」の絞り込みは使えなくなります。「見る人」で選んだ人が優先されるためです。

### 自分の仕事の見つけ方

毎朝これだけやれば、その日にやることが決まります。3つの手順で終わります。

- **手順1 画面を開く**: 配られた URL を開くか、`index.html` をダブルクリックします。
- **手順2 「見る人」で自分の名前を選ぶ**: 選んだ瞬間、タスクの画面はその人の行だけになります。
- **手順3 「タスク」を開いて期限の早い順に見る**: 上の「期限順」を押すと期限順に並びます。「遅れだけ」を押すと、期限を過ぎてまだ終わっていないものだけが残ります。

自分のタスクを見つけたら、次の3つを確かめます。

- 何を（タスクの題）
- いつまでに（期限）
- どうなったら終わりか（完了の定義）

3つ目の「完了の定義」は、カードにカーソルを当てると自動で開きます。押すと右から詳しい欄が開きます。この3つが埋まっていないものは、そもそもタスクとして起こされない決まりになっています。だから「何をすればいいのか分からないタスク」は原則として存在しません。もし分からなければ、それは書き方の問題なので、その場で PM に言って直してもらってください。

### タスクの状態は6語だけ

状態を表す言葉は次の6つだけです。**新しい言葉を作らないでください。** 「ほぼ完了」「だいたい終わってる」は状態ではありません。迷ったら「進行中」か「レビュー待ち」のどちらかにしておき、判断は会議でします。

| 状態 | 意味 | 見本での例 |
|---|---|---|
| 未着手 | まだ手を付けていない | 紹介元3社へ追加募集を依頼する |
| 進行中 | 自分の手で進めている | 受け入れ手順書の残り12項目を書く |
| レビュー待ち | 自分の手を離れて相手の番 | 書類確認の案をレビューに出す |
| ブロック | 自分の作業では動かせない | 面談する人の追加の稟議を出す |
| 完了 | 終わった。記録を添えてある | — |
| 中止 | やらないことにした | — |

この6語に「保留」はありません。担当・期限・完了の定義のどれかが埋まらないものは、そもそもタスクにしません。会議録の④にある「保留」の行に、理由と再検討日を書いて残します。

「ブロック」にしたときは、**詰まりそのものを課題として1件必ず起こします**。ブロックだけ置いて課題を起こさないと、誰もその詰まりを解消しに動きません。この2つはひと組で扱います。

### 「完了の定義」と、完了にするときに添えるもの

タスクには必ず「完了の定義」が付いています。**何があれば終わりなのか**を、他の人が見て○×を付けられる形で書いたものです。

見本のタスク T-05「紹介元3社へ追加募集を依頼する」の完了の定義は、次のようになっています。

> **完了の定義（見本 T-05）**: 3社すべてに依頼が届き、追加で出せる人数の返答が来ている

ここで「依頼する」で終わりにしていないのが要点です。「依頼した」は自分だけで言えてしまいます。「返答が来ている」なら、誰が見ても○か×かが付きます。完了の定義は、いつもこの形で書きます。

そして完了にするときは、**証跡（しょうせき）**を必ず添えます。証跡とは、あとからクリックか検索で辿れるもの、つまりファイルの置き場所か URL のことです。「〜のやり取り」「〜のリンク」といった文章は証跡になりません。**証跡が空のままの「完了」は認められません。**

さらに、完了かどうかは自分で決めて終わりではありません。次の会議の最初（⓪）で、全員が証跡を見て確かめます。確認する責任者は PM です。専門の判断が要るときだけ、その場で確認する人を決めて会議録に書きます。

### 画面については、やってはいけないことが1つだけあります

> **やってはいけない1つ**: 画面のファイル（index.html）を手で書き換えないでください。中に埋め込まれている数字の部分も含めてです。良かれと思って数字を合わせに行くと、正本と画面のどちらが本当か誰にも分からなくなります。直したいときは正本（20_project/）を直し、道具で画面を作り直します。

残りは全部やって大丈夫です。押して壊れるボタンはありません。画面のどのボタンを押しても、「見る人」を切り替えても、「看板」と「期限順」を行き来しても、画面の色を切り替えても、URL を同僚に送っても、スマートフォンで開いても問題ありません。画面は正本から作ったものなので、正本さえ残っていれば何をしても元に戻せます。

## 3章 フォルダとファイルの構成

ここまでは「見る側」の話でした。ここからは「本物が置いてある側」の話に移ります。この章を読み終えると、画面に出ているどの数字についても、元のファイルまで辿れるようになります。

### 全体の並び

フォルダ一式を開くと、数字で始まる名前のフォルダが並んでいます。この番号は**置き場所を表す番号**で、読む順ではありません。あとから新しいフォルダを足しても番号を振り直さなくて済むように、間を空けて番号が振ってあります。

```
00_foundation/     全員が守る約束（6つ）
20_project/        ここが正本。数字も決定もタスクもここ
30_semantic_map/   言葉の一覧
40_process_map/    週の流れと、人が決める場所
60_outputs/        画面（正本から作る）
tools/             道具（画面の作り直し・名前の入れ替え）
docs/              この手引き
README.md          人が最初に開く1枚
names.yml          組織名・人の名前・期間を書くファイル
NORMS.md           迷ったとき何が何に勝つか
CLAUDE.md          AI の道具が自動で読む案内
AGENTS.md          同上（別の道具向け）
```

**読み方**: 左がフォルダかファイルの名前、右がその中身の説明です。上から順に番号が振ってあります。

**先に結論を言うと、メンバーが触るのは 20_project/ の中だけ**です。番号のついたフォルダは5つ（ほかに tools と docs）ありますが、普段開くのは1つです。残りは「そういうフォルダがある」と知っておけば十分で、必要になったときに読めば間に合います。


### フォルダは、それぞれ何のためにあるか

| フォルダ | 何のため | いま使うか |
|---|---|---|
| 00_foundation | 全員が守る約束（6つ） | 使用中 |
| **20_project** | **唯一の正本。決めごと・数字・タスク・記録** | **使用中** |
| 30_semantic_map | 言葉の一覧（用語 → 一言の訳） | 使用中 |
| 40_process_map | 週の流れと、人が決める場所 | 使用中 |
| 60_outputs | 画面（正本から作る） | 使用中 |
| tools（番号なし） | 画面の作り直しと名前の入れ替え | 使用中 |
| docs（番号なし） | この手引き | 使用中 |

この配布キットは、支援側が管理する元の一式から、運用に要るフォルダだけを写したものです。元の一式にある「まだ使わない」フォルダ（外から来た資料の受け取り口・引き継ぎ・気づき・教訓・保管）は、必要になったときに支援側が足します。

### いちばん上に置いてある5枚のファイル

フォルダではなく、1枚もののファイルが5つ、いちばん上に置いてあります。人が読むのは上の3枚で、下の2枚は AI が自動で読みます。

| ファイル | 役割 | 中身 |
|---|---|---|
| README.md | 人が最初に読む1枚 | 全体像・いまどこ・週の回し方 |
| names.yml | 名前を書くファイル | 組織名・人の名前・期間・会議の枠 |
| NORMS.md | 優先順位 | 迷ったとき何が何に勝つか |

`CLAUDE.md` と `AGENTS.md` は、AI の道具が自動で読む案内です。規則の本文は書かれておらず、上の3枚への指差しと「やってはいけない5つ」だけが入っています。**人は読まなくて構いません。**

`NORMS.md` の優先順位は、上から順に「先方の社内規程・契約 → この一式の形の出どころ → この一式の約束 → 各フォルダの説明 → ファイル冒頭の但し書き」です。上のほうが勝ちます。同じ段なら、範囲の狭いほうが勝ちます。書いてあるものが、推測や口頭の話に勝ちます。

### `20_project/` の中身は13点

正本のフォルダの中身です。番号は読む順ではなく置き場所です。**毎週触るのは 03 と 04 の2つだけ**で、残りは決めたときや起きたときに触ります。

| ファイル | 持っているもの | 更新のリズム |
|---|---|---|
| 00_charter.md | 立ち上げの決めごと8項目 | 発足時に1回 |
| 01_plan.md | 範囲・成果物のまとまり・体制 | 計画時 |
| 02_kpi_tree.md | 測る数字の定義と目標 | 計画時・月に1回 |
| **03_dashboard.md** | **今週の数字と今週の一言** | **毎週・会議の前** |
| **04_tasks/** | **タスク 1件1ファイル** | **会議で起こす・随時** |
| 05_decision_log.md | 決めたことと、その理由 | 決めたその日 |
| 06_risk_ledger.md | 起きるかもしれないこと | 週に1回・月に1回 |
| 07_issue_ledger.md | もう起きて止めていること | 起きたその日 |
| 08_stakeholders.md | 関係者と、関わりの深さ | 立ち上げ時・月に1回 |
| 09_meetings/ | 会議の定義と、1回ごとの記録 | 毎回 |
| 10_closing.md | 終わりの点検9項目と完了報告 | 終わりに1回 |
| 11_change_log.md | 範囲・期限・予算を変えたい申し出 | 出たその日 |
| targets.yml | 数値目標の機械用の形 | 道具が作る |

`00_charter.md`（立ち上げの決めごと）には、何のためにやるか・何が出れば成功か・誰が責任者か・誰が承認するかが8項目で入っています。プロジェクトを始めるときに1回埋めて、そのあとは重要な決定の場でしか変えません。ここが埋まっていないプロジェクトは、終わり方が決まらないまま走り続けることになります。

`targets.yml` は道具が作る生成物です。**手で直さないでください。**

### メンバーが自分で書き込むのは、`04_tasks/` の中だけ

タスクは**1件につきファイル1つ**です。ファイル名がそのまま管理番号になります。`T-05.md` なら管理番号は `T-05` です。番号は起こした順で、途中で完了したものがあっても欠番は詰めません。

新しいタスクを作るときは3つの手順です。

- **手順1**: 同じフォルダにある `_template.md`（雛形）をコピーする。
- **手順2**: ファイル名を空いている番号にする（`T-09.md` など）。
- **手順3**: ファイルの上のほうにある欄を埋める。

この作業は AI に頼めます（4章）。手で作る必要はありません。ただし AI も、担当・期限・完了の定義の3つが決まらないタスクは作りません。そこは人が決めるところだからです。

### タスク1件の実物

説明だけでは形が分からないので、見本のタスク `20_project/04_tasks/T-05.md` を全文そのまま出します。

```
---
id: "T-05"
title: "紹介元3社へ追加募集を依頼する"
wp: "WP-02"
assignee: "リーダー（サンプル）"
due: "2026-09-11"
status: "未着手"
definition_of_done: "3社すべてに依頼が届き、追加で出せる人数の返答が来ている"
related: ["PJ-2026Q3-talent-sample/RSK-02"]
evidence: []
---

# T-05 — 紹介元3社へ追加募集を依頼する

出所: MTG-talent-sample-20260828/A-04（見本）

## 内容

未面談の候補者は114人（132人 − 面談済18人）。これから必要な打診は
週10人 × 9週 ＝ 90人 で、いまは24人の余裕。辞退・連絡不通が2割を
超えると足りなくなるため、先に追加募集を打っておく。

## 更新の記録（追記だけ）

| 日付 | 誰が | 変更 | 一言 |
| 2026-08-28 | リーダー（サンプル） | 起票（未着手） | 会議④で決定 |
```

**読み方**: 上の2本の区切り線に挟まれた部分が欄、その下が本文です。この形は雛形と同じで、どのタスクも同じ並びになります。

全部ただの文字なので、メモ帳でも開けます。画面のタスクのカードに出ているのは、この欄の中身そのものです。

読み方は3つ押さえれば十分です。

- 欄は9つあります。必ず要るのが7つ、任意が2つです。
- **欄は増やしません。** ここにない欄を作らないという決まりです。
- 長い説明や証跡がたくさんあるときは、別のファイルに書いて、ここからは置き場所だけを指します。

### 9つの欄が、それぞれ何を意味するか

| 欄 | 日本語で言うと | 何を書くか |
|---|---|---|
| id | 管理番号 | ファイル名と同じ番号 |
| title | 題 | 何をどこまでやるか |
| wp | どのまとまりか | どの成果物のまとまりに属するか |
| assignee | 担当 | 1人だけ |
| due | 期限 | 年-月-日 |
| status | 状態 | 6語から1つ |
| definition_of_done | 完了の定義 | 何があれば完了か |
| related（任意） | 関連 | 関係する課題・リスクの番号 |
| evidence（任意） | 証跡 | 完了時は必須。置き場所か URL |

**担当は必ず1人**です。2人で分担するときは、タスクを2件に割ります。1件に2人を書くと、どちらが動くのかが決まらないまま止まるからです。

**wp の欄は「どの成果物のまとまりに属するか」**です。まとまりは計画のファイル `01_plan.md` に一覧があり、`WP-01` から `WP-12` までの番号が振られています。どのまとまりにも属さない小さな事務作業は `—` と書きます。

任意の2つ（`related` と `evidence`）は、要らなければ行ごと書かなくて構いません。ただし**完了にするときは evidence が必須**です。

### タスクを動かすとき、書き換えるのは2か所です

作業が進んで状態が変わったら、書き換えるのは次の2か所だけです。

- **状態の欄を書き換える**: `status: "未着手"` を `status: "進行中"` にする、というだけです。完了にするときは `evidence`（証跡）も一緒に埋めます。
- **本文の「更新の記録」に1行足す**: 日付・誰が・何を変えたか・一言、の4つを書きます。上書きせず、足すだけです。過去の行は消しません。あとから「なぜこうなったのか」を辿れるようにするためです。

黙って変えてはいけないものが2つあります。

**期限を延ばすとき**は、「最初の期限 → いまの期限」を並べて書き、なぜ延ばしたかを会議で1行残します。黙って延ばすと、期限までに終わった割合（実行率）が実態と合わなくなります。

**担当を替えるとき**は、「担当（いま／前）」の形に直し、交代の理由を決定として1行残します。不在のときの代理も同じ扱いです。

このほか、タスクが大きくなりすぎたときは子のタスクを新しい番号で起こし、子の内容欄に「親: `T-NN`」と書き残します。子が全部終わった時点で親を完了にします。

### 画面の数字から、元のファイルまでの辿り方

画面に出ているどの数字も、次の矢印を逆にたどれば、必ず1つのファイルの1行に着きます。

<!-- flow -->
正本（20_project/ の中の .md と .yml）
　　↓　道具が読む
道具（python3 tools/build_dashboard.py）
　　↓　書き出す
画面の中に埋め込まれた数字
　　↓　画面が組み立てる
あなたが見ている画面

数字の出どころを知りたいときは、この向きを逆に辿ります。手順は3つです。

- **手順1**: 画面のどの欄の数字かを見る（例: 全体の画面の「いま 4人」）。
- **手順2**: `20_project/03_dashboard.md` を開く。今週の実績・鮮度・週ごとの値がここにあります。
- **手順3**: 目標や数え方を知りたいなら `02_kpi_tree.md`、計画や体制なら `01_plan.md`、タスクなら `04_tasks/` を開く。

ここで大事なのは、**正本には「元の数」だけが置いてあり、割り算や判定は画面のほうがしている**という分け方です。達成の割合・実行率・必要ペース・今日までの予定・遅れ・残り日数などは、画面が計算しています。こうしておくと、元の数と画面の数字が食い違う経路そのものが生まれません。

### やってみます — 画面の「週8人」はどこから来たのか

会議で「その数字はどこから？」と聞かれたときに、この順で答えられます。全部、電卓で確かめられる割り算です。

| 式 | 結果 | 元のファイル |
|---|---|---|
| 確定4人 ÷ 面談18人 | 確定率 22% | 03_dashboard.md |
| 18 ÷ 4 | 確定1人に面談4.5人 | 03_dashboard.md |
| 目標20人 × 4.5 | 必要な面談 90人 | 02_kpi_tree.md |
| 90 ÷ 面談できる12週 | 週7.5 → 週8人 | 03_dashboard.md |
| 90 − 面談済18 | 残り 72人 | 03_dashboard.md |
| 72 ÷ 残り9週 | 必要ペース 週8人 | 03_dashboard.md |

この計算は、正本の `03_dashboard.md` に「この画面の数字の出し方」として17行すべて書いてあります。だから「誰かの頭の中にしかない数字」が画面に出ることはありません。もし辿れない数字を見つけたら、それは不具合です。PM に伝えてください。

なお、この割り算は「確定1人に必要な面談 4.5人」を軸にすると全部割り切れます。20人 × 4.5 ＝ 90人、16人 × 4.5 ＝ 72人、72 ÷ 9週 ＝ 週8人、というふうに、途中で端数が出ません。

## 4章 AI への頼み方

この一式は、AI に手伝わせることを前提に作られています。ここでいう AI は、ブラウザで開くチャットのことではありません。**このプロジェクトのフォルダを開いた状態で動く AI の道具**のことです。フォルダを開いているので、中のファイルを自分で読み、必要なら書き換えます。

### そもそも「プロンプト」「コマンド」「スキル」とは何か

この3つは、どれも身構えるような言葉ではありません。最初に意味を1つに決めておきます。

- **プロンプト**: AI に打つ文章そのものです。普通の日本語で構いません。「T-05 を進行中にして」でも通じます。
- **コマンド**: 半角のスラッシュ（`/`）で始まる、短い合図です。長い説明を毎回書かなくて済むように、よく使う頼みごとに短い名前を付けたものです。このプロジェクトで覚えるコマンドは `/talent` の1つだけです。
- **スキル**: そのコマンドを打ったときに、AI が読みにいく**手順書のファイル**です。このプロジェクトのスキルは `.claude/skills/talent/SKILL.md` にあります。人が読んでも構いません。何を読み、何をして、どこで止まるかが日本語で書いてあります。

つまり `/talent` と打つことは、「この手順書のとおりにやってください」と頼むことと同じです。手順書に書かれていないことは AI もやりません。

### 打つ前に確かめる3つ

- **AI の道具を開く**: Claude Code か Codex を立ち上げます。どちらも文字で会話する道具です。
- **このプロジェクトのフォルダを開く**: ここがいちばん大事です。フォルダを開いていない AI は、このプロジェクトの中身を何も知りません。
- **入力欄にスラッシュから打つ**: 会話の入力欄に、半角スラッシュで始まる言葉を打ちます。

打つのは、たとえば次の1行だけです。

```
/talent 今週
```

**読み方**: これで1行です。スラッシュから始めて、talent、半角スペース、動詞の順に打ちます。

`talent` は「タレント」と読みます。打つのはここまでで、あとは普通の日本語で会話できます。専門用語を覚える必要はありません。

### 覚えるコマンドは `/talent` の1つだけ

覚えることを増やさないために、コマンドは1つだけにして、そのあとに続ける言葉で行き先を分けています。この5つ以外を覚える必要はありません。迷ったら `/talent 今週` から始めてください。

| 打つ言葉 | やってくれること |
|---|---|
| /talent 今週 | 今週の状態を読み、会議の前にやることを出す |
| /talent タスク | タスクを起こす・状態を変える |
| /talent 画面 | 正本から画面を作り直す |
| /talent 会議 | 会議録を作り、決めたことを記録へ入れる |
| /talent 名前 | 組織名・担当者名・期間・会議の枠を入れ替える |

以下では、この5つそれぞれについて「実際に打つ言葉」「返ってくるもの」「AI が止まる場所」を順に見ます。

#### ① `/talent 今週` — 会議の前にやることを出してもらう

週の初め、または会議の前日に1回打ちます。いちばん多く使う頼み方です。

**実際に打つ言葉**: `/talent 今週`

**AI が自動で読むファイル**: 今週の数字（`20_project/03_dashboard.md`）、タスク全件（`20_project/04_tasks/`）、リスクと課題（`06_risk_ledger.md`・`07_issue_ledger.md`）、次の会議の枠（`09_meetings/bodies/weekly.md`）。人がファイルを指定する必要はありません。

**返ってくるもの**: 次の4つが並びます。

- 鮮度が古くなっている数字の一覧
- 期限が来ている、または過ぎているタスク
- 兆候が出ているリスクと、いま対応中の課題
- 次の会議までに誰が何を更新するか（担当ごとに1行）

**AI が止まる場所**: 数字を推測で埋めません。分からない値は「未計測」と書いて止まります。ここで AI が勝手に数字を埋めないのは、埋めた瞬間に「誰かの頭の中にしかない数字」が記録に入ってしまうからです。

#### ② `/talent タスク` — 起こす・状態を変える・完了にする

会議で決まったことをタスクにするときと、自分の作業が進んだときに使います。

**実際に打つ言葉**: `/talent タスク` と打ってから、普通の日本語で続けます。たとえば「T-05 を進行中にして」「面談枠の見直しをタスクにして」のように書けば通じます。

**返ってくるもの**:

- 新しいタスクのファイル（`T-09.md` など）
- 状態の書き換えと、「更新の記録」への1行の追記
- 変えたあとに画面を作り直すようにという案内

**AI が止まる場所**: 担当・期限・完了の定義を推測で埋めません。分からなければ人に聞いて止まります。また、証跡が空のまま「完了」にはしません。

止まったときは、人が決める番です。「担当は誰にしますか」「いつまでにしますか」「何があれば終わりですか」と聞かれます。この3つが決まらないものは、タスクにせず、会議録の「保留」の行に理由と再検討日を書きます。ここで無理にタスクにしてしまうと、誰も動かないタスクが1件増えるだけになります。

#### ③ `/talent 画面` — 正本から画面を作り直す

正本の数字やタスクを変えたあと、必ず1回やります。1つの命令で終わります。

**実際に打つ言葉**: `/talent 画面`。自分で直接打つなら次の2行です。

```
python3 tools/build_dashboard.py
python3 tools/build_dashboard.py --check
```

**読み方**: 上の行が画面を作り直す命令、下の行が正本と画面が一致しているか確かめる命令です。上から順に1回ずつ実行します。

**返ってくるもの**: 作り直された画面のファイルと、確認の結果です。確認の結果は数字で返ってきます。

| 結果 | 意味 | どうするか |
|---|---|---|
| 0 | 正本と画面が一致している | ブラウザで開いて確かめる |
| 1 | 画面が古い | 作り直しをもう一度実行する |
| 2 | 正本の書き方が間違っている | 表示された場所を直す |

**AI が止まる場所**: 正本の書き方に間違いがあると、**1文字も書かずに止まり**、どのファイルの何行目かを表示します。途中まで書いて壊れることはありません。担当の書き方が計画のファイルと一致していない場合も、ここで止まります。

#### ④ `/talent 会議` — 会議録を作り、決めたことを記録へ入れる

会議の直前と、会議が終わる5分前に使います。

**実際に打つ言葉**: `/talent 会議`

**返ってくるもの**:

- その回の会議録のファイル
- ⓪から⑥までの並びに沿った記入欄
- 決めたことを4つの記録へ振り分ける案内
- 次回の日時と議題の書き込み

**AI が止まる場所**: 決めていないことを、決まったことにしません。担当・期限・完了の定義が埋まらない決定は、タスクにせず「保留」に置きます。

会議の最後5分で閉じる5項目も、この言葉で頼めます。中身は5章に書きます。

#### ⑤ `/talent 名前` — 見本の名前を、自分たちの名前に入れ替える

最初に1回だけ使います。組織名・プロジェクト名・担当者名・期間・会議の枠が、文章の中も画面の中もまとめて入れ替わります。

**実際に打つ言葉**: `/talent 名前`。自分で直接打つなら次の順です。

```
python3 tools/apply_names.py --rename
python3 tools/apply_names.py --check
python3 tools/build_dashboard.py
python3 tools/build_dashboard.py --check
```

**読み方**: 上から順に1回ずつ実行します。1行目が文章の名前、3行目が画面の名前を入れ替えます。--check の付いた行は、やり残しがないかを確かめるだけで、何も書き換えません。

**返ってくるもの**: 文章の中の名前がすべて入れ替わり、画面の名前の欄も入れ替わります。入れ替える前の値は `names.applied.yml` という控えのファイルに残ります。

**AI が止まる場所**: 値が空・知らない項目がある・期間の書き方が食い違う、のどれかがあれば、**1バイトも書かずに止まります**。

ここで気をつけることが1つあります。**固有名を1つずつ手で置き換えないでください。** 名前を書く場所は `names.yml` の1か所だけで、そこを直して上の命令を順に1回ずつ実行します。手で置き換えると、必ずどこかに古い名前が残ります。なお、数字・タスク・リスク・会議の日付は「名前」ではないので、`20_project/` のほうを直します。

### AI が必ず止まる場所

ここに挙げたことは、AI も PM も、人の GO が出るまで進めません。逆に、ここに書いていないことでは止めません。

| 止まる場所 | GO を出す人 | 何があれば進めるか |
|---|---|---|
| 立ち上げの決めごとの承認 | 承認者（サンプル） | 8項目が埋まり、3条件が YES |
| 期限・予算・範囲の変更 | リーダー（サンプル） | 変更の申し出と、影響の評価 |
| 終わりの判定（完了／中止） | リーダー（サンプル） | 終わりの点検9項目と完了報告 |
| 危険（🔴）の知らせ | PM が即日リーダーへ | 危険と判断した理由1行と対応の案 |
| 画面の公開・URL の変更 | リーダーと支援側 | 個人情報が入っていない確認 |

逆に、次のことでは止めません。今週の数字の更新、タスクを起こすことと状態の変更、課題を起こすこと、会議のやり方を試してみること、気づきを書き残すこと。これらは PM の判断で進めて構いません。いちいち承認を取りに行くと、週が回らなくなります。

### AI に頼むときに気をつけること

- **AI も画面のファイルを手では直しません。** 直したいときは正本を直して作り直します。もし AI が画面を直接書き換えようとしたら、それは誤りなので止めてください。
- **AI が「分かりません」と止まったら、それは正常な動きです。** 推測で埋めないことが、この一式でのいちばん大事な約束だからです。
- **打った言葉と返ってきた内容は、そのまま会議で見せられます。** 隠す必要はありません。

## 5章 週の回し方

### 週は4つの区切りで1周します

この運用は、毎週同じ順で「数字を見る → 決める → タスクにする → 次の週の最初に確かめる」を回します。区切りは4つです。

| 区切り | 誰が | 何をするか |
|---|---|---|
| 会議の前日まで | PM（**当面は支援側が代行**） | 今週の数字を更新し、画面を作り直す |
| 会議当日 | 全員 | ⓪から⑥の順で60分 |
| 会議の最後5分 | PM（**当面は支援側が代行**） | 5項目を閉じてから解散する |
| 週の途中 | 各担当 | タスクを進め、状態と証跡を残す |

> **当面の分担（引き渡しまで）**: 「PM」の行は支援側が代行します。PM がやるのは **会議の2日前までに、数字（今週の数字の5つの段と鮮度・今週の一言・今週これを決める）を支援側の担当へ送る** ことです。形式は正本の表をそのまま（値だけ）で構いません。宛先は支援側の担当（`names.yml` の OUR_CONTACT_NAME に記入）です。引き渡し後は、この表のとおり PM が行います。

締切を曜日で書かないのが、この運用の細かいけれど大事な約束です。「会議の前日まで」「会議が終わる前」と書きます。こうしておくと、会議の枠を動かしたときに締切も一緒に動きます。曜日を直接書くと、枠を変えたときに締切だけが取り残されます。

そして、この3つ（数字を見る・決める・タスクにする）はひと組です。**1つが止まると全部止まります。** 今週の数字の更新が済んでいない週は、会議を始めません。数字がないまま集まっても、話が印象論になるからです。

### 会議の前日まで — PM が2つやります（当面は支援側が代行）

ここが済んでいないと会議は始まりません。所要は10分ほどです。当面は、PM が数字を送り、下の2つは支援側が代行します（引き渡し後は PM が行います）。

**その1、今週の数字を更新します。** `20_project/03_dashboard.md` を開いて、次の4つを書きます。

- 5つの段の数字と、それぞれの鮮度（いつの値か）。この5つの段は、正本の中で「1段目」から「5段目」と書かれている5つの区分のことです
- 「今週の一言」— 何が詰まっているかを1つだけ言い切る
- 「今週これを決める」— 最大2件
- 「週ごとの値」の表に、今週の行を1行足す（上書きしない）

**その2、画面を作り直します。** AI に頼むなら `/talent 画面` です。自分で打つなら `python3 tools/build_dashboard.py` を実行し、続けて `--check` を付けて実行します。結果が 0 なら正本と画面が一致しています。最後にブラウザで開いて目で確かめます。

ここで守ることが1つあります。**基準日は1つにそろえてください。** 1回の更新の中で、数字の日付をばらばらにしないという意味です。画面の中に「いつの値か」が2つ以上あると、あとから「どれを見て判断したのか」が誰にも分からなくなります。古い数字は、無いのと同じではありません。正しいと思って読まれるぶん、無いより悪い扱いです。

### 会議当日 — 毎週この並びで進めます

見本では毎週月曜の09:00から10:00までの60分です。並びは固定で、順番を入れ替えません。

| # | 議題 | 時間 |
|---|---|---|
| ⓪ | 前回タスクの確認（証跡を見る） | 10分 |
| ① | 数字の確認（5つの段を読み上げる） | 10分 |
| ② | 原因の話し合い（律速はどこか） | ②③で最長 |
| ③ | 施策の話し合い（今週決めることを決める） | — |
| ④ | 決定 → タスク化 | 10分・必ず確保 |
| ⑤ | 課題・リスク・変更の申し出の見直し | 5分 |
| ⑥ | 気づき（行き先を1つ選ぶ） | 5分 |

**⓪ を飛ばした瞬間に、この会議は形だけのものになります。** 決めたことが追われなくなり、「後で割り振り」が増え、期限までに終わった割合が実態と合わなくなります。⓪ は10分かかっても飛ばしません。

④ に「必ず確保」と書いてあるのも同じ理由です。決めるところまでで時間切れになると、決めたことがタスクにならないまま週が終わります。

### 会議の最後5分 — PM が5つ閉じてから解散します

ここを次の日に回すと、決めたことの半分が、誰も追わないまま消えます。閉じる責任者は PM です。

- **その1**: 決めたことを全部タスクにする。担当1人・期限・完了の定義を付けて、`04_tasks/` に1件1ファイルで置きます。
- **その2**: 4つの記録へ入れる。決定は `05_decision_log.md`、詰まりは `07_issue_ledger.md`、リスクは `06_risk_ledger.md`、変更の申し出は `11_change_log.md` です。
- **その3**: 決めどころを入れ替える。決まった分を今週の数字から外し、次週の分（最大2件）を入れます。
- **その4**: 次回の日時と議題を、会議の定義のファイルの「次回」の欄に書きます。
- **その5**: 画面を作り直して確かめる。AI に `/talent 画面` と頼んでも構いません。

### 週の途中 — メンバーがやることは3つだけ

毎日30秒で終わります。ためると、次の会議の⓪で全部まとめて出てきます。

- **自分のタスクを進める**: 画面の「見る人」を自分にして、期限の早い順に見ます。
- **状態を変えたら1行足す**: `04_tasks/` の自分のファイルの状態を書き換え、「更新の記録」に1行足します。
- **詰まったら早く言う**: 自分の力で動かせない詰まりは「ブロック」にして、課題を1件起こします。

3つ目が特に大事です。**「ブロック」にしたら、詰まりそのものを課題として1件必ず起こします。** これがひと組です。ブロックだけ置いて課題を起こさないと、誰もその詰まりを解消しに動きません。

### 月に1回やること

月の初めに、60分から90分の見直しをします。ここで見るのは、その週だけでは気づけないことです。

- リスクの3点検（新しく出たもの・もう心配ないものの整理・実際に起きたもの）
- 範囲がふくらんでいないかの見直し
- 測っている数字がまだ正しいかの見直し
- 関係者の見直しと、負担の配り直し
- 律速がどこに移ったかの確認

律速は動きます。詰まっていたところで処理できる数が増えると、次に少ないところが律速になります。印を付け替えたら、付け替えた日を1行残します。

### この6つが出たら、会議が形だけになりかけています

どれか出たら、会議の⑥（気づき）で取り上げます。責める話ではなく、直す合図です。

- ⓪（前回の確認）が省かれた、または「後で割り振り」が出た
- 1週間より古い数字のまま、数字の確認が進んだ
- 期限が黙って延びた（「最初の期限 → いまの期限」の併記がない）
- 危険（🔴）が2週続いているのに、決める場が開かれていない
- 「今週これを決める」が2週続けて同じまま
- 律速が変わらないまま、手前や後ろの数字だけが増えている

このうち、いちばん見つけやすいのは5つ目です。「今週これを決める」が2週続けて同じなら、決める人か、判断の材料のどちらかが足りていません。

## 6章 守ること・困ったとき

### 守ることは6つだけです

これ以外は試して構いません。うまくいったやり方は会議で共有すると、手順の型になります。

- **本物は 20_project/ の中だけ**: 数字・決定・タスク・リスクを直すときは、ここを直します。
- **画面のファイルを手で書き換えない**: 中の数字も含めてです。作り直しは道具の1つの命令です。
- **状態の言葉を発明しない**: 「ほぼ完了」は状態ではありません。決められた言葉から選びます。
- **記録は消さない。足す**: 却下になった申し出も、外れたリスクも、行を残して状態だけ変えます。
- **数字には「いつの値か」を必ず添える**: 鮮度が1週間を超えた数字で判断しません。
- **個人情報・録音・パスワードを置かない**: メールアドレス・電話番号・録音・文字起こし・パスワード・接続用のキーは入れません。

最後の1つは、この一式が誰かに共有されても困らない状態を保つための約束です。人の名前は、先方と合意した表記だけを使います。

### 困ったときは、症状からこの表を引きます

どれも「聞く前に自分で確かめられる」場所です。それでも分からなければ PM に聞いてください。

| こう思ったとき | 開く場所 | そこに何があるか |
|---|---|---|
| この言葉は何だろう | 30_semantic_map/glossary.md | 用語 → 一言の訳 |
| これは誰が決めるのか | 40_process_map/weekly_triangle.md | 人が決める場所 |
| どっちが正しいのか迷う | NORMS.md | 何が何に勝つかの順位 |
