# 運転席の使い方 — メンバー向けの手引き

**この手引きは誰のためのものか**: 人材プロジェクトに関わるリーダー・PM・メンバーの方。パソコンかスマートフォンでブラウザが開ければ読めます。プログラムの知識は要りません。

**読むと何ができるようになるか**: 運転席（プロジェクトの「いま」を1枚で見る画面）を自分で開き、自分のタスクを見つけ、週の会議に必要な準備ができるようになります。

**読む順**: 上から順に読んでください。1〜3章で画面を開いて見る、4〜5章で自分の仕事を進める、6章で週を回す、7章は困ったときだけ開きます。

> **見本データ**: いま画面に出ている数字・人名・タスクは、すべて練習用の見本です。実在の人や実績ではありません。皆さんの実際の数字が入るのは、値をいただいて画面を作り直した後です。この手引きは「画面の読み方を覚えるためのもの」として読んでください。

## 1. 運転席とは何か

運転席は、プロジェクトの「いま」を1枚で見るための画面です。計器盤・タスク・メンバー・会議 の4つの画面が、上の切り替えで入れ替わります。

覚えておいてほしい性質が1つあります。この画面は鏡です。数字そのものを画面が持っているわけではなく、別の場所にある元の文書から自動で写し取っています。ですから、画面の数字を直接書き換えることはできませんし、してはいけません。数字を直したいときは元の文書を直し、担当者が画面を作り直します。手で直すと、元の文書と画面のどちらが最新なのか、誰にも分からなくなるからです。

<!-- box: 説明 -->
> **正本と投影**: 正本（せいほん）は、数字や決定が本当に書いてある元の文書のことです。この案件では `20_project/` というフォルダにあります。 引き渡しまでは、支援側が管理する元のリポジトリ側の `20_project/` が正本で、この配布キットの `20_project/` は凍結した見本です。投影（とうえい）は、正本から自動で作った見せ方のことです。運転席は投影で、正本ではありません。

## 2. 開き方

ブラウザで次のURLを開きます。ブックマークしておくと便利です。

**URL**: 支援側が公開して PM へ渡し、PM がメンバーへ配ります（この配布キットには URL を置きません）。PM の方は、支援側の担当から URL を受け取ってください。

- **URL の出どころ**: 支援側が公開します。画面を作り直したら、同じ URL へ差し替えるよう支援側へ依頼します（依頼しない限り URL の先は古い画面のままです）。
- **ログイン**: 要りません。URLを知っている人だけが開けます。人に渡すときは、渡してよい相手かを確かめてください（外部への公開・URLの変更は、リーダーと支援側の承認が要ります）。
- **スマートフォン**: 開けます。画面の幅に合わせて並びが変わります。
- **配色**: 右上の「ダーク」を押すと暗い配色になります。目が疲れるときにどうぞ。
- **画面のいちばん下**: 「作り直し日」と「鮮度」（その数字がいつ時点のものか）、そして画面に出る言葉をまとめた「ことば」があります。**鮮度が1週間を超えた数字では判断しません。**

## 3. 4つの画面 — それぞれが1つの問いに答えます

知りたいことで画面を選んでください。「いつ見るか」は**この手引きの目安**で、正本が定める締切ではありません（正本の締切は6章の表にあるものだけです）。

| 画面 | 答える問い | 主に見る人 | いつ見るか |
|---|---|---|---|
| **計器盤** | いま健全か。今週何を決めるか | リーダー | 週のはじめ・会議の前 |
| **タスク** | 自分は何を、いつまでにやるのか | 全員 | 毎日 |
| **メンバー** | 誰が何を握っていて、進んでいるか | リーダー・PM | 週1回・詰まったとき |
| **会議** | 前回はできたか。今週何を決めるか | 出席者 | 会議の前日と当日 |

### 計器盤 — 上から順に読むと話が通ります

計器盤は7つの節が縦に並んでいます。上から順に読むと、この週の結論から手元の詰まりまで、話が通るようになっています。

- **今週の一言**: この週の結論が1行。詳しくは「続きを見る」を押します。
- **健全性の5つの観点**: スケジュール・スコープ・品質・チーム・リスクの5つに、丸印と「健全／注意／危険」の言葉と、そう判定した理由が付きます。色だけでなく必ず言葉が添えてあるので、色が見分けにくい方でも読めます。
- **最終目標（KGI）のゲージ**: 半円の弧に4つの点が重なった図です。この画面でいちばん大事なところなので、読み方を次の項でくわしく説明します。
- **今週決めること**: まだ決まっていない選択肢が並びます。「その案を採ると期限日にどこへ着地するか」が棒の長さで見えます。
- **途中の数字（KPI）**: 最終目標の手前にある数字が4枚。値・前週との差・推移・達成の割合・その数字がいつ時点のものかが載ります。
- **スケジュール**: 全期間を1本の帯にして、節目（フェーズ）と今日の位置を示します。
- **タスクの状態／効いているリスクと課題**: 手元がどれだけ片づいているか、いま効いている心配ごとは何か。

<!-- box: 説明 -->
> **KGI・KPI・KDI**: KGI は最終的に達成したい数字（これが達成なら成功）。KPI はそこへ向かう途中の数字。KDI は自分たちで動かせる行動の数（週に何本、といった量）です。この案件の KGI は「受け入れ確定人数」で、KPI は面談の本数や確定の割合、KDI は週あたりの面談数にあたります。

#### 最終目標（KGI）のゲージの読み方

ゲージには4つの点が重なっています。この4つを読み分けられれば、計器盤は読めます。

- **いま**: 現在の実績。
- **今日までの予定**: 計画どおりに進んでいれば、今日この数になっているはずの数。
- **このペースの見込み**: いまの速さのまま期限日を迎えたら、いくつになるかの試算。
- **目標**: 期限までに届かせたい数。

**いちばん見るべき差**: 「このペースの見込み」と「目標」の差です。ここに差があるなら、いまのやり方のままでは届きません。何を変えるかを会議で決めることになります。

<!-- box: 説明 -->
> **律速と必要ペース**: 律速（りっそく）は、いちばん詰まっていて全体の速さを決めている一段のことです。ここを直さないと、手前や後ろをいくら足しても総量は増えません。必要ペースは「残りの必要量 ÷ 残りの週数」で、週にどれだけ進めば期限に届くかを表します。どちらもゲージのすぐ下に1行で出ます。

### タスク — 看板と一覧表を切り替えられます

- **看板**: 状態ごとの縦の列にカードが積まれます。列の高さが、そのままどこで詰まっているかを表します。
- **一覧表**: 1行1件で期限順に並びます。期限や担当を見比べるときはこちらです。
- **完了の定義**: カードや行を開くと出ます。何をもって「終わり」とするかの条件です。ここを読まずに着手しないでください。
- **絞り込み**: 状態・担当・遅れだけ、で絞れます。次章の「見る人」を使っているあいだ、担当の絞り込みはそちらに譲って止まります。

### メンバー — 人ごとのカード

人ごとに1枚のカードがあり、役割・担当している成果物の束・月別の稼働（その人の時間のうち、このプロジェクトに使う割合）・現役タスクと状態の内訳・今週の行動量・次の期限が並びます。現役とは、完了と中止以外の状態のことで、画面の表に出るのは現役だけです。

<!-- box: 説明 -->
> **WP（成果物の束）**: Work Package の略で、一連の成果物のまとまりのことです。1週間以内に「終わった」と言える大きさに割ってあります。カードには束の名前と状態が出ます。**A** は説明責任を持つ人（束ごとに1人だけ）、**R** は実行する人を表します。

### 会議 — 「前回 → 今週 → 次回」の3枚

左が前回の検収、中央が今週の実行率・遅れ・決めること、右が次回の出席者・議題・会議の前日までにやることです。その下に「決めたこと」が日付順に並びます。検収（けんしゅう）とは、終わったと言われたものを証跡（終わったと言える記録）で確かめることです。

<!-- box: 説明 -->
> **DEC・RSK・ISS**: それぞれ「決定」「リスク（これから起きるかもしれないこと）」「課題（もう起きていて、進行を止めていること）」の略です。画面では日本語の言葉が先に出るので、略語を覚える必要はありません。

## 4. 自分のタスクの見つけ方（3手）

<!-- flow -->
1手目　画面の右上の「見る人」を、「全体」から自分の名前に変える
　　↓　
2手目　計器盤に「この人の今週」が出る（行動量・自分のタスク・持っている束・前回の会議の分）
　　↓　
3手目　上の「タスク」へ切り替える。自分の行だけになるので、「完了の定義」を読んでから始める

全体に戻すときは、「見る人」で「全体」を選びます。

## 5. タスクを進めるときに守ること

- **状態の言葉は決まったものから選ぶ**: 未着手／進行中／レビュー待ち／ブロック／完了／中止 の6つだけです。「ほぼ完了」「だいたい終わってる」は状態ではありません。迷ったら「進行中」か「レビュー待ち」に倒し、判断は会議で行います。
- **終わりの判断は「完了の定義」で行う**: 自分の感覚ではなく、カードに書いてある条件を満たしたかどうかで決めます。
- **詰まったら「ブロック」にして理由を書く**: すでに起きていて進行を止めていることは、**その日のうちに「課題」として起票します**（会議を待ちません）。黙って止まっているのがいちばん困ります。
- **期限を黙って延ばさない**: 延ばすときは、最初の期限と今の期限の両方を残します。黙って延びた期限は、運転がうまく回っていないサインとして見ています。
- **担当は1人にする**: 「みんなで」は担当ではありません。担当1人・期限・完了の定義がそろって、はじめてタスクです。

## 6. 週の回し方

会議は毎週決まった枠で開きます（見本では月曜 09:00〜10:00）。締切は「月曜まで」のような曜日ではなく、「会議の前日まで」「会議の最後5分」のように、会議からの相対で決めてあります。会議の枠を動かせば、締切もそのままついてきます。

| いつ | 誰が | 何をする |
|---|---|---|
| **会議の前日まで** | PM（**当面は支援側が代行**） | 元の文書を更新し、画面を作り直す（会議の入場券） |
| **会議のはじめまで** | メンバー全員 | タスクの状態を最新にし、終わったものは証跡を残す（会議⓪の検収がこれを見ます。正本が定める前日締切は上のPMの1行だけです） |
| **会議のはじめ** | 全員 | 前回のタスクの検収。ここを飛ばさない |
| **会議の中盤** | 全員 | 数字の確認 → 律速の特定 → 今週決めることの決定 |
| **会議の終わり** | 全員 | 決めたことを全部タスクにする |
| **会議の最後5分** | PM（**当面は支援側が代行**） | 台帳へ記入し、次回の議題を置き、画面を作り直す |
| **週の途中** | 担当者 | 実行して証跡を残し、タスクの状態を更新する |

> **当面の分担（引き渡しまで）**: 「PM」の行は支援側が代行します。PM がやるのは **会議の2日前までに、数字（計器盤の1〜5段の値と鮮度・今週の一言・今週決めること）を支援側の担当へ送る** ことです。形式は元の文書の表をそのまま（値だけ）で構いません。宛先は支援側の担当（`names.yml` の OUR_CONTACT_NAME に記入）です。引き渡し後は、この表のとおり PM が行います。

> **決めどころと決定は別物**: 「今週これを決める」（決めどころ）はまだ決まっていない選択肢で、計器盤に出ます。会議で決まったら「決定」として台帳へ移り、計器盤の欄は次の選択肢に入れ替わります。同じ決めどころが2週続けて残っているときは、決める人か材料が足りていないサインです。

## 7. 困ったときの入口

| 症状 | どうするか |
|---|---|
| **画面が開かない** | URLを確かめる。それでも開かないなら PM へ |
| **数字が古い** | 画面の下の「作り直し日」と「鮮度」を見る。**鮮度が1週間を超えていたら** PM へ（1週間を超えた数字で判断しないのが決まりです） |
| **数字が合わない** | 画面を直さない。元の文書のどこが違うかを PM へ伝える |
| **タスクが出ない** | 「見る人」と絞り込みを確かめる。それでも無ければ PM へ |
| **言葉が分からない** | 画面のいちばん下の「ことば」を開く |

## 8. AIへの頼み方（5つの言葉）

この案件では、このフォルダの中で AI に頼めることが5つ決まっています。**打つのは日本語の1行**で、プログラムの知識は要りません。5つ以外の言い方でも通じますが、この5つが決まった入口です。

<!-- box: 説明 -->
> **どこで打つのか**: このフォルダ（`04_project-operations/talent-sample/`）で AI（Claude Code）を開いて、下の言葉を打ちます。開き方が分からないときは PM に聞いてください。

- **`/talent 今週`** — 会議の前にやることを出してもらう。鮮度が古い数字・期限が来ているタスク・効いているリスクと課題を挙げ、次の会議までに誰が何を更新するかを担当ごとに1行で出します。
- **`/talent タスク`** — タスクを起票する・状態を変える。**担当1人・期限・完了の定義**の3つが埋まらないものは、AIが起票を止めます。完了にするときは証跡が要ります。
- **`/talent 画面`** — 正本から画面を作り直す。数字を直したあとは必ずこれです（画面を手で書き換えないため）。作り直したあと、4つの画面をPC幅とスマホ幅で見るところまでやってくれます。
- **`/talent 会議`** — 会議録を作り、決めたことを台帳へ入れる。⓪の検収から⑥まで順に進め、最後の5分で閉じるところまで案内します。
- **`/talent 名前`** — 組織名・プロジェクト名・担当者名・期間・会議の枠を入れ替える。見本の名前を自分たちの名前にするときに使います。

<!-- box: 強調 -->
> **AIに任せないこと**: 憲章の承認、期限・予算・範囲の変更、終結の判定は**人が決めます**。AIはそこで止まります。数字を推測で埋めることもしません（分からない値は「未計測」と書きます）。

## 付録: この画面に出る言葉

#### 仕組みの言葉

- **正本（せいほん）**: 数字や決定が本当に書いてある元の文書。直すときはここを直す。
- **投影（とうえい）**: 正本から自動で作った見せ方。運転席のこと。手では直さない。
- **鮮度（せんど）**: その数字がいつ時点のものか。週ごとに回す仕事では、1週間を超えた数字で判断しない。
- **証跡（しょうせき）**: 終わったと言える記録。検収はこれを見て行う。
- **検収（けんしゅう）**: 終わったと言われたものを、証跡で確かめること。

#### 数字の言葉

- **KGI**: 最終目標の数字。これが達成なら成功。
- **KPI**: KGI へ向かう途中の数字。
- **KDI**: 自分たちで動かせる行動の数（週あたり）。
- **律速（りっそく）**: いちばん詰まっていて、全体の速さを決めている一段。
- **必要ペース**: 残りの必要量 ÷ 残りの週数。週にどれだけ進めば期限に届くか。
- **今日までの予定**: 今日の時点で届いているはずの数。
- **着地（見込み）**: いまの進み方のまま期限日を迎えたときに届く数の試算。

#### 記録の言葉

- **DEC（決定）**: もう決まったことと、その理由。
- **決めどころ**: 「今週これを決める」のこと。まだ決まっていない選択肢で、決まったら決定へ移る。
- **RSK（リスク）**: これから起きるかもしれないこと。
- **ISS（課題）**: もう起きていて、進行を止めていること。

#### 仕事の単位の言葉

- **WP（ワークパッケージ）**: 成果物の束。1週間以内に「終わった」と言える大きさに割る。
- **タスク**: 担当1人・期限・完了の定義がそろった具体作業。
- **完了の定義**: 何をもって「終わり」とするかの条件。
- **現役（のタスク）**: 完了・中止以外の状態。画面の表に出るのは現役だけ。
- **遅れ**: 期限が今日より前なのに、まだ現役のもの。

## この手引きの出どころ

- **画面の版**: 配布キット（このフォルダ）の配布版 2026-09-04（第1版）。
- **画面の見方**: `60_outputs/dashboard/README.md`。
- **週の回し方**: `40_process_map/weekly_triangle.md`。
- **言葉**: `30_semantic_map/glossary.md`。
- **数字と期限**: 本文に出る「月曜 09:00〜10:00」は見本の会議枠です。数字・期限・担当の正しい値はいつも元の文書と画面にあり、この手引きはその読み方だけを案内します。食い違ったときは元の文書が優先します。

## 9. 実案件にするとき・引き渡すとき・戻すとき（支援側と PM の確認表）

| いつ | 何をする | 誰が |
|---|---|---|
| **実案件にするとき** | 見本の履歴（タスク8件・会議録2本・週の値3行）をそのまま使わない。支援側が見本を除いた初期状態を作り、`names.yml` を先方の値にしてから運転を始める | 支援側 |
| **引き渡しの前** | 引き渡しまで、実データの正本は支援側が管理する元のリポジトリです。このフォルダは凍結した見本で、**公開中は実データを入れない・同期しない** | 支援側 |
| **引き渡し（このフォルダを正本にする）** | **先方の管理者がこのリポジトリを非公開にする**（支援側にはその権限がありません）。非公開になったことを確認してから、日時・支援側の書き込み停止・最終の版・公開する人と URL の管理者・戻し先の版を1組で決める。README の1行を書き換えるだけでは引き渡しにならない | 先方の管理者・支援側 |
| **引き渡しの受入** | 新しい運転者が、実際に1件を更新 → 画面を作り直す → 公開 → URL で開く、までを1回通す | PM |
| **戻すとき** | 引き渡し後に新しく入った更新を回収してから、支援側の版へ戻す（二重に書かない） | 支援側 |
