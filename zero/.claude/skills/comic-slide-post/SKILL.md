# コミックスライド投稿制作スキル（一気通貫パイプライン）

投稿ネタの選定から画像生成プロンプトの完成までを、4フェーズのパイプラインで進めるスキル。

このスキルの肝は **「既存スキルを工程として連結する」** こと。文章化は `contents-craft`、圧縮は `info-slide` の手順にそれぞれ完全準拠し、このスキルは工程間の受け渡しと最終出力（スライドごとのプロンプト化）に責任を持つ。

---

## このスキルが発動する条件

以下のキーワードがあれば発動する：

- 「投稿を作りたい」「投稿作って」「新しい投稿を作ろう」
- 「ネタリストから作って」「ネタリストの〇〇で作って」
- 「コミックスライドにして」「スライド投稿にして」
- 「画像生成用のプロンプトまで作って」

逆に発動しないケース：

- 「記事だけ書きたい」「noteを書きたい」 → `contents-craft` 単体を使う
- 「このテキストを圧縮メモにして」 → `info-slide` 単体を使う
- 途中の工程から始めたい場合 → 該当フェーズから開始する（後述「途中参加のルール」）

---

## 前提ファイル

このスキルはプロジェクト内の以下のファイルを参照する。開始時に必ず読み込むこと。

| ファイル | 役割 |
|---|---|
| `ネタリスト.md` | 投稿ネタのストック。Phase 1 でここからネタを選ぶ |
| `見本.md` | 完成プロンプトの見本。「# レイアウト&情報整理」「# デザイン設計」のセクションを Phase 4 でそのまま流用する |
| `.claude/skills/contents-craft/SKILL.md` | Phase 2 の手順書 |
| `.claude/skills/info-slide/SKILL.md` | Phase 3 の手順書 |

## 処理フロー（4フェーズ）

```
Phase 1: ネタ選定（ネタリスト.md から選ぶ）
  ↓
Phase 2: 文章化（contents-craft に準拠して長文コンテンツを作る）
  ↓
Phase 3: 圧縮（info-slide に準拠して N枚分の圧縮メモにする）
  ↓
Phase 4: プロンプト化（各1枚に見本.md のレイアウト・デザイン設計を付ける）
  ↓
出力（1枚目〜N枚目の画像生成プロンプト + ネタリスト.md のステータス更新）
```

### Phase 1: ネタ選定（確認1往復）

1. `ネタリスト.md` を読み込み、「ストック 🌱」のネタを一覧提示する
2. ユーザーが指定したネタを選ぶ（ユーザーが最初からネタ名を指定していれば提示は省略）
3. ネタリストに何もない・ユーザーが新ネタを出した場合は、そのネタを `ネタリスト.md` のストックに追記してから進める
4. 選んだネタの「狙い・伝えたいこと」「ターゲット」を確認し、不足していればここで1往復だけ質問する

提示テンプレ：

```
【ネタリストのストック】
1. 〇〇（狙い：〇〇 / ターゲット：〇〇）
2. 〇〇（狙い：〇〇 / ターゲット：〇〇）
...

どのネタで投稿を作りますか？（番号 or 新しいネタでもOK）
```

ネタが確定したら、`ネタリスト.md` の該当ネタを「制作中 ✍️」に移動する。

### Phase 2: 文章化（contents-craft に準拠）

`.claude/skills/contents-craft/SKILL.md` を読み込み、その4フェーズ（型の確定 → 材料収集 → 構成設計 → 文章化）に **完全準拠** して長文コンテンツを作る。

このスキル側での補足ルール：

- テーマ・読者は Phase 1 で確定済みの「ネタ・ターゲット」をそのまま引き継ぐ（再質問しない）
- 最終的にスライドに圧縮する前提なので、章数は **3〜6章** を目安にする（1章 ≒ スライド1枚に対応させやすくするため）
- 完成原稿は Markdown で出力し、ユーザーの OK をもらってから Phase 3 へ進む

### Phase 3: 圧縮（info-slide に準拠）

`.claude/skills/info-slide/SKILL.md` を読み込み、Phase 2 の完成原稿を入力として **N枚分の圧縮メモ** に変換する。

このスキル側での補足ルール：

- 分解の単位は基本的に「1章 = 1枚」とする（章が長い・短い場合は info-slide の分解判定に従って調整）
- 各1枚は info-slide の共通規格（接続詞で論理を見せる文章・400字前後・構造化ラベルなし）を守る
- 捏造防止ルールは info-slide のものに従う（原稿にない数字・事実を足さない）
- 圧縮メモを提示し、ユーザーの OK（枚数・分け方・タイトルへの合意）をもらってから Phase 4 へ進む

### Phase 4: プロンプト化（見本.md のレイアウト・デザイン設計を合体）

各1枚の圧縮メモを、`見本.md` と同じ構造の **画像生成プロンプト** に変換する。

手順：

1. `見本.md` を読み込み、「# レイアウト&情報整理」と「# デザイン設計」のセクションを **一字一句そのまま** 取り出す
2. 各1枚につき、以下の構造でプロンプトを組み立てる：
   - 冒頭の指示文（見本.md の冒頭文をそのまま使う）
   - `# 内容` … その1枚の圧縮メモ（タイトル + 本文）
   - `# レイアウト&情報整理` … 見本.md からの流用
   - `# デザイン設計` … 見本.md からの流用
3. 1枚目〜N枚目まで、すべての枚数分を出力する

各1枚のプロンプト構造：

```
【N枚目】
----------------------------------------

↓の内容をデザイン設計に基づいてイラスト図解の画像にして
文章などは適宜短くしたり省略していい


# 内容
（Phase 3 で作ったその1枚のタイトルと本文）

# レイアウト&情報整理
（見本.md のセクションをそのまま）

# デザイン設計
（見本.md のセクションをそのまま）

----------------------------------------
```

ルール：

- レイアウト&情報整理・デザイン設計は **編集しない**（全スライドでデザインの一貫性を保つため）。変えたい場合は `見本.md` 自体を更新してもらう
- 変わるのは `# 内容` だけ
- 各枚は `【1枚目】` `【2枚目】` のラベルと区切り線で明確に分離する
- プレーンテキストで出力する（画像生成AIにそのままコピペできる形）

### 仕上げ：ネタリストの更新

全プロンプトの出力が終わったら：

1. `ネタリスト.md` の該当ネタを「投稿済み ✅」…ではなく **「制作中 ✍️」のまま進捗メモを更新** する（画像生成と投稿はユーザーの作業のため）
2. 「投稿が完了したら教えてください。ネタリストを投稿済みに更新します」と伝える
3. ユーザーから投稿完了の報告があれば「投稿済み ✅」に移動し、投稿日を記録する

## 途中参加のルール

ユーザーが途中の成果物を既に持っている場合は、該当フェーズから始める：

| ユーザーの状態 | 開始フェーズ |
|---|---|
| ネタも文章もない | Phase 1 から |
| ネタは決まっている | Phase 2 から（ネタリストへの記録だけ行う） |
| 長文原稿がある（「この記事をスライドにして」） | Phase 3 から |
| 圧縮メモまである（「これをプロンプトにして」） | Phase 4 から |

---

## 修正指示の受け方

一発生成後、ユーザーが指示を出したら該当フェーズに戻って該当部分だけ直す：

| 指示の例 | 対応 |
|---|---|
| 「3枚目の内容を変えて」 | Phase 3 の該当1枚だけ再圧縮 → その1枚だけプロンプト再生成 |
| 「2枚目と3枚目をくっつけて」 | info-slide の結合ルールで統合 → プロンプト再生成（枚数ラベル振り直し） |
| 「元の文章から直したい」 | Phase 2 に戻って該当章を修正 → 以降のフェーズをやり直し |
| 「デザインを変えたい」 | `見本.md` の該当セクションを更新 → 全枚のプロンプトを再生成 |
| 「タイトルだけ変えて」 | 該当1枚のタイトルのみ差し替え |

---

## 出力形式

- 各フェーズの結果は対話形式（テキスト）で返す
- 最終出力（プロンプト）はプレーンテキストで、1枚ずつコピペできる形にする
- HTML Artifact は使わない
- 各フェーズの完了時に「次のフェーズに進みます」と明示する
- 最終出力は `posts/` フォルダなどへのファイル保存をユーザーに提案してよい（例：`posts/001_ネタ名/プロンプト.md`）
