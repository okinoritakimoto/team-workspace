# 長文コンテンツ対話制作スキル

長文系コンテンツ（note・ブログ・書籍・長尺記事）を、ユーザーの思考を誘導しながら4フェーズで仕上げる。

このスキルの肝は **「型を最初に決めることで、その後のフェーズが自動最適化される」** こと。テーマだけでなく型（投稿パターン）を選ばせることで、必要な材料と構成が一気に決まる。

---

## このスキルが発動する条件

以下のキーワードがあれば発動する：

- 「noteを書きたい」「note作って」「ブログ書きたい」
- 「記事を作って」「長文を作って」「コンテンツを作って」
- 「〇〇についてまとめたい」「〇〇についての記事」
- 「読み物にしたい」「書籍にしたい」「章立てで書きたい」

逆に発動しないケース：
- 「診断を作って」「クイズを作って」 → `shindan-pop` / `study-quiz` を使う
- 「短いSNS投稿を作って」 → このスキルは長文向け（章立てが必要な分量）
- 「要約して」「まとめて」 → 単発要約タスクなのでスキル不要

---

## 制作前にユーザーから引き出す情報

最初の1ターンで以下を読み取る。不足は **Phase 1の中で順次質問**するため、ここで全部聞き出す必要はない。

| 項目 | タイミング | 推定値 |
|------|-----------|--------|
| テーマ | ユーザー入力から抽出 | 必須（ない場合は質問） |
| 型（投稿パターン） | Phase 1で選ばせる | テーマから3〜5型を提示 |
| 読者 | Phase 1の補助確認 | 不明なら「想定読者は誰ですか？」で確認 |
| 読後変化 | Phase 1の補助確認 | 不明なら「読んだ人にどうなって欲しいですか？」で確認 |
| 文字数感 | 必要なら確認 | 指定なし → 章数で調整（目安：3〜6章） |

## システム設計の手順（必ず順番通りに行う）

### Phase 1: テーマと型の確定（確認重視・往復必須）

**型から入る**ことで、Phase 2の視点とPhase 3の構成テンプレが自動で決まる。

進め方：

1. ユーザーがテーマを投げる
2. AI側でテーマに合いそうな**投稿パターンを3〜5型ピックアップ**し、**具体的なタイトル候補（型名は末尾の注釈）として提示**する
3. ユーザーがタイトル候補を選択（「全部見たい」と言われたら8型カタログを全部出す）
4. **補助情報を1往復で確認**：
   - 読者：「誰に届けるか」（例：AI初心者 / マーケティング担当者 / 経営者）
   - 読後変化：「読んだ人にどうなって欲しいか」（例：今すぐ試したくなる / 価値観が揺さぶられる / 安心する）
5. 「この型と方向で確定？」で確認 → OKなら次へ

#### ステップ2-3で使うテンプレ：タイトル候補の提示

**タイトルを主に出し、型名は末尾のカッコ内に注釈として添える**。ユーザーが見るのはタイトル＝完成イメージなので、型名はあくまで補足。

```
【テーマ：〇〇】に合いそうなタイトル候補を提示します。気になるものを選んでください。

A.「〇〇をゼロから使いこなす5ステップ」（ロードマップ型）
B.「〇〇で使える機能25選」（網羅情報型）
C.「〇〇するときに絶対やってはいけない7つのこと」（注意喚起型）
D.「〇〇は本当に〇〇か？」（神話崩し型）

「全部の型を見たい」と言われたら8型カタログを全展開する。
```

参考例（テーマに応じて適宜書き換えること）：

| テーマ | 提示するタイトル候補（型は注釈） |
|---|---|
| AI活用 | 「AIをゼロから使いこなす5ステップ」（ロードマップ型）/ 「2026年に試したいAI活用シーン25選」（網羅情報型）/ 「AIを使うときに絶対やってはいけない7つのこと」（注意喚起型）/ 「AIに仕事を奪われる、は本当か？」（神話崩し型） |
| ダイエット | 「ダイエットで一番大事なのは"これ"だけ」（結論型）/ 「カロリー制限は嘘だった」（神話崩し型）/ 「20kg痩せて分かった、本当に効いた習慣」（物語型）/ 「リバウンドを招く7つの習慣」（注意喚起型） |
| 読書術 | 「年100冊読む人になる4ステップ」（ロードマップ型）/ 「本嫌いだった私が読書家になった話」（物語型）/ 「速読 vs 精読、どっちを選ぶべきか」（比較対比型）/ 「読書で人生が変わる人と変わらない人の違い」（結論型） |

#### ステップ4-5で使うテンプレ：方向性の最終確認

```
【方向性の確認】
テーマ：〇〇
型：〇〇型
読者：〇〇
読後変化：〇〇

この方向で進めて大丈夫ですか？
（修正したい場所があれば指定してください）
```

### Phase 2: 材料収集（網羅・スピード重視）

Phase 1で選ばれた型に応じて、AI側が必要な視点を自動選定する。

**最初に「コンテンツ1本として成立する王道セット（パッケージ）」を1ブロックで提示**し、その下に「他のパーツ候補（差し替え・追加用）」を視点ごとに並べる。ユーザーは王道セットで進めるのが基本で、変えたいパーツがあれば指定する。**選別を強要しない**のがポイント。

進め方：

1. 型 → 視点マッピング表（後述）から **5〜8視点** を選ぶ
2. **王道セット**：選んだ視点を1つずつ埋めて、これだけでコンテンツが1本成立するパッケージとして提示する
3. **他のパーツ候補**：視点ごとに5〜10個ずつ並べる（差し替え・追加の選択肢）
4. ユーザーエピソードもヒアリング（差別化の核）
5. ユーザーは「変えたい・追加したいパーツだけ指定」する（なければスルーで王道のまま進める）

#### 提示テンプレ（1回で完結）

王道セットに並ぶ視点は **Phase 1で選ばれた型に応じて変わる**（後述の「型 × 必要視点 マッピング」表を参照）。下記は注意喚起型を想定した例。

```
【〇〇型 × テーマ「〇〇」の材料案】

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 王道セット（このまま使えばコンテンツが1本成立します）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- 科学的根拠：〇〇
- 成功事例：〇〇
- 失敗事例：〇〇
- 比喩：〇〇
- 誤解パターン：〇〇
- 読者の日常シーン：〇〇

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 他のパーツ候補（差し替え or 追加したいときに）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

▼ 科学的根拠（追加候補）
  1-1. ……
  1-2. ……
  1-3. ……
  1-4. ……
  1-5. ……

▼ 成功事例（追加候補）
  2-1. ……
  2-2. ……
  2-3. ……
  2-4. ……
  2-5. ……

▼ 失敗事例（追加候補）
  3-1. ……
  3-2. ……
  3-3. ……

（以下、各視点同様）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【ユーザーエピソード】
このテーマについて、あなた自身の体験はありますか？（1〜2個でOK／なければ「なし」）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

→ 王道セットでこのまま進めます。
   差し替えや追加したいパーツがあれば番号で指定してください（なければスルーでOK）。
```

「読者の日常シーン」と「ユーザーエピソード」の違い：

- **読者の日常シーン**：AI側で想像できる、読者が共感する典型シーン（王道セットに含める）
- **ユーザーエピソード**：書き手自身の体験。AI側では出せないので別ブロックでヒアリングする（最大の差別化要素）

#### 進める判断

- ユーザーが番号を指定（追加） → 王道セットに追加してPhase 3へ
- ユーザーが「1-3に変えて」など → 王道の該当パーツを置き換えてPhase 3へ
- ユーザーが「このまま」「OK」「なし」など → 王道セットだけでPhase 3へ
- ユーザーが「全部入れて」など → 全候補を採用（情報過多になる場合は警告）

### Phase 3: 構成設計（確認1往復）

Phase 1で選ばれた型に対応する構成テンプレを使う。

**ユーザーには目次レベルで簡潔に見せる**。材料割り当て・章末の引きなどの詳細設計はAI内部で保持し、Phase 4の文章化で使う。

進め方：

1. 型に対応する構成テンプレで章タイトルを設計
2. **ユーザー提示用**：章タイトル（読者が読みたくなる問い・章名）を箇条書きで並べる
3. **AI内部用**：各章に「内容・使う材料・章末の引き」を裏で設計しておく（ユーザーには見せない）
4. ユーザー確認1往復で確定（目次に対して「OK / 章を足す・減らす / 順序変更 / タイトル変更」を受け付ける）

#### ユーザー提示用（目次レベル）

提示の形式（汎用テンプレ）：

```
【構成案】

1. （章タイトル）
2. （章タイトル）
3. （章タイトル）
...

この構成で進めて大丈夫ですか？
（章の追加・削除・順序変更・タイトル修正があれば指定してください）
```

章タイトルの書き方ポイント：
- 「読者が読みたくなる問い」または「中身が一目で分かる名詞句」
- 章数は3〜6が目安（テーマや分量に応じて増減）
- 「使う材料」「章末の引き」はユーザーに見せない（情報過多になる）

参考例（テーマ：「ハンタウイルス」を時事解説型で書く場合）：

```
1. 起こったこと + 懸念されている事実
2. ハンタウイルスってなんなの？
3. パンデミックの可能性はあるの？
4. なぜクルーズ船で広がるの？
5. 日本へのリスクは？
6. まとめ
```

※あくまで参考例。テーマに応じて適切な章タイトルに書き換えること。

#### AI内部用（裏で保持する詳細設計）

ユーザーが目次OKを出した後、Phase 4で執筆する際にAI側で参照する設計図。各章につき以下3項目を保持する。

- **内容**：その章で何を伝えるか（1〜2文）
- **使う材料**：Phase 2で確定した材料セットからどれを使うか
- **章末の引き**：次章への誘導フレーズ

参考例（同じくハンタウイルスがテーマの場合）：

```
第1章：起こったこと + 懸念されている事実
  - 内容：時系列で発生事実を整理し、なぜ警戒されているかを示す
  - 使う材料：王道-科学的根拠, 王道-成功事例
  - 章末の引き：「ではそもそもハンタウイルスとは何か」

第2章：ハンタウイルスってなんなの？
  - 内容：基本情報（感染経路・症状）を分かりやすく
  - 使う材料：王道-科学的根拠, 比喩
  - 章末の引き：「では今回パンデミックは起きるのか」
```

※テーマ・型に応じて書き換えること。

### Phase 4: 文章化（第1章で雰囲気確定 → 残り一気書き）

3段階で進める。**章ごとに毎回確認するのではなく、最初の1章でトーンを確定**させることで、雰囲気のブレと修正コストを防ぐ。

#### 4-1. 第1章のみ執筆 → ユーザー確認

擦り合わせる観点を明示してから書く：

```
【第1章を執筆します】
このあとユーザーに確認していただく観点：
- トーン（カジュアル / フラット / 熱量高め）
- 文体（です・ます / である / 体言止め混ぜる）
- 密度（読ませる文 / サクサク読める文）
- 一文の長さ・リズム

────────
（第1章の本文）
────────

トーン・文体・密度・リズムはいかがですか？
- このまま全章書く
- 修正したい（具体的に指定してください）
```

#### 4-2. 残り全章を一気に執筆

ユーザーOKなら、第1章を「お手本」として固定し、トーン/文体/密度を崩さずに残り全章を書く。各章の冒頭で前章を受け、各章の末尾で次章への引きを入れる。

#### 4-3. 全体の磨き

- **冒頭フックの強化**：読者が一行目で離脱しないか確認・調整
- **章間のつなぎ**：前章を受けて次章へ自然に流れているか
- **終章の余韻**：読後の感情を設計（行動喚起 / 余韻 / 問いかけのいずれか）

完成原稿はMarkdownで一括出力する。

## 投稿パターン カタログ（8型）

| 型 | 中身 | 典型タイトル例 | 向くテーマ |
|---|------|---------|---------|
| ロードマップ型 | 順序立てた手順・ステップ | 「〇〇するための5ステップ」 | スキル習得・プロセス系 |
| 網羅情報型 | 並列に大量列挙 | 「〇〇で使える機能20選」 | ツール紹介・選択肢提示 |
| 注意喚起型 | 失敗・落とし穴・やってはいけない | 「〇〇するときに絶対避けるべき7つのこと」 | 失敗回避・リスク管理 |
| 結論型 | 明快な主張を冒頭で打つ | 「〇〇の本質はこれだ」 | 自分の考えを伝える |
| 物語型 | 体験・ストーリーで読ませる | 「〇〇を始めて人生が変わった話」 | 体験談・自己開示 |
| 比較対比型 | A vs B / Before-After | 「〇〇と××どちらを選ぶべきか」 | 選択判断・変化提示 |
| 神話崩し型 | 通説への反証 | 「〇〇は嘘だった」「実は誤解されている〇〇」 | 既存常識への挑戦 |
| 問題解決型 | 課題→原因→解決 | 「〇〇で悩む人が知るべき原因と解決策」 | 悩み解決・コンサル系 |

## 型 × 必要視点 マッピング

Phase 1で型が決まると、Phase 2で集めるべき視点が自動で決まる。

| 選ばれた型 | 重点視点 |
|---|---|
| ロードマップ型 | 段階別エビデンス + 各段階の成功/失敗事例 + 比喩（プロセスを腑に落とす） |
| 網羅情報型 | 並列大量出し（とにかく数）+ 軽い分類 + 用途別の使い分け |
| 注意喚起型 | 失敗事例 + 誤解 + リスク + 反例 + 警告フレーズ |
| 結論型 | 主張を支えるエビデンス + 反論への反論 + 強い比喩 |
| 物語型 | 体験 + 感情 + 名言 + 比喩 + 転換点 + 現在地 |
| 比較対比型 | 両陣営の事例 + 数値比較 + 評価軸定義 |
| 神話崩し型 | 通説の整理 + 反証エビデンス + 実態事例 + 「なぜ誤解が広まったか」 |
| 問題解決型 | 問題事例 + メカニズム（原因の構造）+ 解決アクション + 効果 |

## 材料の視点リスト（5レイヤー）

型からマッピングされる視点は、以下の5レイヤーから選ばれる。

| レイヤー | 視点 |
|---------|------|
| エビデンス系 | 科学的根拠 / 統計・数値 / メカニズム説明 |
| 事例系 | 成功事例 / 失敗事例 / 歴史的事例 / 有名人・企業の例 / 身近な事例 |
| 対立軸系 | 反例・反論 / 例外パターン / よくある誤解 |
| 表現装置系 | 比喩・たとえ話 / 名言・引用 / アナロジー / 問いかけ |
| 個人化系 | ユーザー固有エピソード / 読者が共感する日常シーン |

## 構成テンプレート集（型と連動）

| 型 | 構成テンプレ |
|---|---|
| ロードマップ型 | 全体像 → Step1 → Step2 → … → Step n → まとめ |
| 網羅情報型 | 導入 → カテゴリA（項目1〜n） → カテゴリB（項目1〜n） → まとめ |
| 注意喚起型 | 危険性の共有 → 落とし穴1 → 2 → … → 正しい方法 → まとめ |
| 結論型 | 結論 → 根拠1 → 根拠2 → 反論への対応 → 再結論 |
| 物語型 | 発端 → 葛藤 → 転換点 → 気づき → 現在の自分 |
| 比較対比型 | 両者の概要 → 評価軸ごとの比較 → ケース別おすすめ → 結論 |
| 神話崩し型 | 通説の提示 → 違和感 → 反証データ → 実態 → 新しい視点 |
| 問題解決型 | 問題提起 → 原因分析 → 解決策 → 実践方法 → 効果 |

## 捏造防止ルール（このスキルの肝）

材料はAI知識ベースで出すため、以下を必ず守る。

### 禁止フレーズ（断定的な引用）

- 「〇〇大学の研究によると」（確証がない限り）
- 「〇〇という論文では」（確証がない限り）
- 「〇〇年の調査では〇〇％が」（確証がない限り）
- 「ハーバードの〇〇教授は」（確証がない限り）

### 推奨フレーズ（一般論・経験則として）

- 「一般に言われている」
- 「〜という考え方が知られている」
- 「経験則として」「実感として」
- 「〜と感じる人は多い」
- 「〇〇という説がある」
- （名言を引用するとき）「〜と言われる」

### 数字の扱い

- 具体的な数字（〇〇％、〇〇倍など）は **確証がない限り使わない**
- どうしても使う場合は「目安として」「ざっくり」と明記
- 「数年で」「多くの人が」「一定数は」など曖昧表現を活用

### 名言・引用の扱い

- 作者が確実な名言のみ氏名を書く
- 不確実なら「〜と言われる」「〜という言葉がある」とぼかす
- 創作した格言は使わない（必ず実在のものか、引用形式を取らない言い回しにする）

### NG例 → OK例

| NG | OK |
|---|---|
| 「ハーバード大学の研究では、〇〇する人は健康寿命が10年延びることが分かっています」 | 「〇〇する人は長期的に健やかでいられる、という考え方が一般に知られています」 |
| 「2023年の調査では70%の人が〇〇と回答しました」 | 「多くの人が〇〇と感じている、というのが実感としてあります」 |
| 「アインシュタインは『〇〇』と言いました」（出典不明な場合） | 「『〇〇』という言葉があります」 |

---

## 出力形式

1. 各フェーズの結果は **対話形式（テキスト）** で返す
2. 完成原稿は **Markdown** で一括出力する
3. **HTML Artifactは使わない**（長文編集に不向き・コピペしづらい）
4. コードブロックや表は必要に応じて使ってよい
5. 各フェーズの完了時に「次のフェーズに進みます」と明示する

## 進行品質チェックリスト

各フェーズで以下を確認する。

### Phase 1 完了時
- [ ] 型を1つに絞り込めたか
- [ ] 読者と読後変化が言語化されているか
- [ ] ユーザーから明示的な「OK」をもらえたか

### Phase 2 完了時
- [ ] 型に応じた視点を5〜8個選定できたか
- [ ] 「王道セット（コンテンツ1本として成立するパッケージ）」を1ブロックで提示できたか
- [ ] その下に「他のパーツ候補」を視点ごとに5〜10個ずつ並べたか
- [ ] ユーザーエピソードをヒアリングしたか
- [ ] ユーザーから差し替え・追加指定があれば反映、なければスルーで王道セットのまま進めたか

### Phase 3 完了時
- [ ] ユーザーには目次レベル（章タイトルだけ）で提示したか
- [ ] AI内部で「内容・使う材料・章末の引き」を詳細設計しているか
- [ ] 章タイトルが型のテンプレに沿っているか
- [ ] 章数が3〜6の範囲に収まっているか（テーマ次第で例外あり）
- [ ] ユーザーから明示的な「OK」をもらえたか

### Phase 4 完了時
- [ ] 第1章でトーンの合意を取れたか
- [ ] 全章のトーンが第1章と一致しているか
- [ ] 冒頭フック・章間つなぎ・終章の余韻が磨かれているか
- [ ] Markdownで出力されているか

## コンテンツ品質チェックリスト

完成原稿を出す前に確認する。

### 内容の正確さ
- [ ] 「研究では」「論文によると」のような断定引用がないか
- [ ] 具体的な数字・論文名・年代に確証があるか（なければ「目安として」表記か）
- [ ] 名言の作者が不明確なものは「〜と言われる」になっているか

### 読みやすさ
- [ ] 一文が長すぎないか（目安：50字以内が中心）
- [ ] 同じ語尾が3回連続で続いていないか
- [ ] 章の冒頭で読者が「何の話か」分かるか
- [ ] 章末で次章への期待が生まれるか

### 構成の整合性
- [ ] 選んだ型のテンプレ通りの順序になっているか
- [ ] Phase 2で確定した材料（王道セット + 追加分）が全て使われているか（または意図的に外したか）
- [ ] 結論・主張が冒頭・本文・終章で一貫しているか

## 応用バリエーション

| バリエーション | 変更点 |
|--------------|--------|
| 短文版（SNS長文） | 章立てを2〜3にして合計1500字程度に圧縮 |
| 書籍版（章ごと独立） | 各章の独立性を高め、章ごとに完結する構成に |
| 連載版（複数記事） | 1記事1型ではなく、シリーズ全体で型を組み合わせる |
| ペルソナ多層 | 読者を「メイン×サブ」の2層で設計し、サブ向け補足を脚注的に挿入 |
